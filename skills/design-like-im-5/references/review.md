# Review

Load this file before pipeline steps 7 through 10.

## Goal

Prove the product in real views and states. A file or code pass is not pixel proof.

## State and view set

Read `state-matrix.json`. Treat its items as an open set. Find missing states from context, events, and transitions before review.

Use the sizes, crops, modes, inputs, content ranges, and motion paths that can change the result. Wide, narrow, whole, close, empty, wait, error, repair, and reduced motion are prompts. They are not a fixed set.

For spatial work, check reach, depth, focus, field of view, and comfort. For games, check input choice, pause, time, cues, focus, and hard actions.

## Model review record

Load `review-checklist.json`. Run its `source_command` to load the full rich checks. Run its `human_source_command` to load the open human sweep. The model must answer every eye, brain, touch, objective failure, bad design, bad output, and bad practice item. Start each answer with a concrete scene from the intake and evidence. Include the person, goal, setting, device, input, prior event, current state, visible change, bodily action, timing, and consequence when known. Do not invent a feeling, ability, culture, or body response. Use `NOT_APPLICABLE` only with seen evidence and a reason.

Apply every named human sweep factor to every item. The list is a required floor and an open set. Add a factor when the current person, body, mind, setting, tool, task, or event reveals one.

For each item, use its one exact question. Follow its probe order. Use its named evidence and failure meaning. Apply its fixed decision rules. Do not replace it with taste, a score, a broad rule, or another item.

Objective failures need a direct render and input check. Inspect text and image edges, crops, layers, active areas, focus, cue loss, state clashes, and all task exits. Missing either proof type means `BLOCKED`.

For each view, list what was seen. State what the eye finds first. State what the person must know. State what the person must touch or control.

Record which choice stayed, changed, or failed. Add the source location, reason, clash, doubt, and linked parts.

The script checks checklist IDs, all named groups, and required fields. It does not score sight, thought, touch, taste, or product fit. The model makes those judgments and names doubt and alternatives.

## Continuous canvas cleanliness

A canvas must stay clean before, during, and after each change. Capture a current whole-canvas view before writing. Keep a clear active work area during each change. This includes create, move, name, style, nest, detach, compare, and delete work. After each small batch, inspect the whole canvas and readable detail. Recheck each stale neighbor and linked part. If direct current sight is missing, mark the affected claim `BLOCKED`.

The eye checks order, groups, crowding, alignment, scale, edges, overlap, clipping, and noise. It tells kept work from trials, rejected work, old work, and quarantine. The brain checks meaning, source, status, test logic, read order, next action, false links, and mental load. Touch checks safe picks, target gaps, reach, blocked views, effort, input changes, edit risk, and recovery after a slip.

Reject bad design when the canvas sets false rank, hides state, mixes owners, blocks access, or fights meaning. Reject bad output when key content is overlapped, clipped, off canvas, unnamed, stale, or mixed across status zones. Copies with no cause and clean claims without current sight are also bad output. Reject bad practice when cleanup is late or proof is removed to look done. Bulk moves and auto layout need readback. Old proof cannot pose as current truth. Neat shapes cannot replace care for the task.

Clean does not mean empty, spare, balanced, or all the same. Keep useful proof with stable names and clear status zones. Tell kept work, trials, rejected work, old work, and quarantine apart. Record changed parts and before-and-after views. Record eye, brain, and touch findings, bad-work calls, kept proof, allowed cleanup, stale links, and the result. One failed check blocks a clean `PASS`.

## Noncompensating quality gate

Apply this gate to the exact scene and product job. Use it after options that differ in a real way. Use it after each shown token, part, layout, or fit state. Use it once more after the last linked change. The checkpoints are `direction`, `artifact`, and `integrated`.

1. `truth`: the content, state, rights, proof, and product sense are true now.
2. `access`: contrast, focus, zoom, reflow, text gaps, targets, input, motion, words, and non-color cues pass the rules that fit.
3. `task`: the person can know, act, fix an error, and finish with fair work and risk.
4. `perception`: rank, groups, contrast, gaps, lines, weight, read order, and change are clear in whole and close views.
5. `familiarity`: controls, paths, words, response, and repair stay known for the type of task.
6. `standards`: the right platform, system, access, and code rules pass. They do not become the art path.
7. `uniqueness`: the new trait shows product sense, helps use or sight, comes back with care, and stays known.
8. `craft`: edges, rhythm, type, icons, planes, motion, fit shifts, and states are made with care instead of copied.
9. `resilience`: wait, empty, error, blocked, off, long text, new words, widths, keys, mouse, and touch keep the set quality.

Each gate needs current proof with a clear place. It also needs proof against, another option, doubt, owners, and a stale rule. Use `DEFECT` when a clear rule fails. Use `MEDIOCRE` when floors pass but the result stays plain or unfinished. Use `SLOP` when intent or ownership is lost. Use `PASS` only when all gates pass. These labels describe seen work, not who made it.

Uniqueness, standards, and familiarity must all pass at once. Do not trade one for another. Known values can make a clear product mark through their links. A new look cannot save odd acts. Known acts cannot excuse a plain product face.

## Controlled comparison gate

Read `references/controlled-comparisons.md` through `mise run test`. Check a fresh one-change pair before an item can pass. Require its shown option and test record to be frozen before sight. Keep the sample, words, state, view size, input path, and other tokens fixed. Use the same eye, brain, touch, fit, input-path, and full quality gates. A missing pair, link, frozen field, current view, or low-owner change makes the item `STALE` or `BLOCKED`.

## Veto order

Safety comes first. Access comes next. Then check sense, agency, task success, known use, voice, new form, and build cost.

Do not trade away safety, access, sense, or agency. Do not hide a cost to make one screen look calm.

## Return

Run the reading check after the full plain read. Run the part check after each low change. Go next to the final package checks.
