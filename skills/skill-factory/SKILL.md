# skill-factory

## Outcome

Create, update, standardize, import and adapt portable skills that accomplish their promised result and supply adequate fresh proof. The unit of acceptance is the complete working capability: instructions, references, assets, configuration, schemas, templates, scripts, workflows, tests, examples, evals, integrations, outputs and maintenance. Apply every rule below to this factory and every skill it generates or updates, through actual independent invocation. Preserve purpose, accepted behavior, source bytes, scope, audience, lineage, independent variants, unrelated work and existing authority. A package that passes checks but cannot serve its intended recipient is unfinished.

**Start here.** Read this whole body first. It owns the core operating rules and the reusable ledger method. On the first loading and every successful later loading, load the entire current governing ledger, its always-required rules and relationships, and the current declared initial resources in their dependency order before their consumers act. The [use-case contract][use-case-contract] owns the resolved outcome, audience, ledger and matrix bindings; the [lifecycle record][lifecycle-record] owns resource roles and loading conditions; the [decision record][decision-record] owns choices and judgments. Missing or ignored required content blocks its consumer. A path, link, digest, previous load or model acknowledgment does not prove actual consumption. The linked records are checked through `mise run use-case-policy`, `mise run primitive-lifecycle-policy` and `mise run decision-policy`; check execution does not replace their required loading. The invoking agent remains responsible for the integrated result after any delegated work.

**Scope and audience key.** This factory has user scope. Every created or updated skill has exactly one string `metadata.scope`: `user` means intended availability across the user's projects; `project` means availability for a particular project or repository. Store the main result consumer once as `audience.primary: human` or `agent` in the owning use-case contract, independently of scope and executor. Derive body and report labels from those canonical fields. Preserve valid values unless the user requests a change or a purpose conflict is resolved. Retain secondary and output-specific audiences when they change requirements. A human result can be produced by an agent; an agent result can have a human report.

Generic wording, installation and registry location cannot decide scope or audience. Resolve material missing or conflicting designation before affected writes; reject duplicate keys, wrong types and invalid values. Untouched legacy inspection can permit absent scope or audience without accepting a changed output. Classification grants no installation, relocation or permission authority; use the [scope contract](references/skill-scope-contract.md) and [variant workflow][variant-workflow] for resolution and authorized placement.

| Key | Action and evidence meaning |
| --- | --- |
| Human result | A person uses or experiences the main result. Test relevant task, comprehension, learning, accessibility, quality or experience outcomes with the actual evidence each claim requires. |
| Agent result | A model or agent consumes the main result. Prove the interface, real downstream semantic use and failure handling; retain material later human consequences. |
| Operation | Name the actual reader, orchestrator, executor, reviewer and authorized decision owner, with required inputs and permitted effects. |
| Mechanical proof | A program establishes its named predicate over captured inputs, with result, coverage and limits. |
| Model assessment | An identified capable model inspects the actual artifact using declared evidence, modalities and criteria. It is not human evidence. |
| Human evidence | A real person supplies the specified preference, observation, expert review, task result or permission. These kinds are distinct. |
| Required or variable | Prerequisites and acceptance gates must hold. Bounded options and open creative choices remain available within the contract. |

**Owners before action.** Inventory the actual humans, models, invoking agent and runner, orchestration tools, programs, runtimes, libraries, services, operating environment, stores, evaluators and relevant resource authorities. Do not invent absent participants or capabilities. Instructions, skills, workflows, schemas, evidence and matrices are owned resources; their presence grants no authority. Assign one effective owner for each definition, execution, permission, data/state, proof/acceptance and maintenance responsibility, with canonical defaults and explicit exceptions in the existing records. For reading, writing, acting, judging, verifying and validating, state who, what, when, how, where and why: source/version and trigger; author versus persistence tool; exact input, target and allowed effect; mechanism or criteria; result and next owner; failure, recovery and acceptance authority. Several explicit roles may belong to one actor, but vague shared ownership, competing writers and missing handoffs fail. Keep private host identities and paths at the integration owner.

## Motivation

A useful skill carries the work through to its recipient's next action. Freeze the intended user, task, starting conditions, artifact or state, boundaries, forbidden outcomes, mandatory methods and adequate proof before implementation. Give every material rule, primitive and decision its domain role, concrete progress value, reason, prevented failure and falsifier. Preserve correctness, intelligence, creativity, craftsmanship, judgment, taste, grounding, proof, validation, safety, scalability and applicable accessibility or other promised qualities. Define those qualities for the actual domain; branding, confidence, file counts, polish, activity and aggregate scores cannot establish them or compensate for a mandatory failure.

Use the smallest coherent structure that preserves the whole contract. Keep one canonical owner per rule, one stable term per concept, one default route per supported situation and explicit necessary failure branches. Remove demonstrated duplication, obsolescence, unused resources and speculative layers without merging different meanings or stripping necessary domain context. Set context and resource budgets for the operation, while retaining every required full read. Read the [writing rules][writing-rules], checked through `mise run lint-writing`, for plain, active, precise language: result first, defined terms, one idea per sentence and one topic per paragraph, in dependency order. Move optional detail only with its destination, owner, exact load trigger and backlink. Counts and lint are diagnostics. The generation contract requires same-meaning human review of clarity and completeness; model assessment does not replace that evidence.

Prevent WorkSlop: apparently completed work that fails its purpose and transfers avoidable interpretation, verification, repair or completion to the recipient. Establish recipient, purpose, context, evidence and next action. The producer checks facts, sources, calculations, behavior and integration; marks drafts, assumptions, decisions and compatibility honestly; and preserves legitimate human review and creative iteration. Do not reward output volume, adoption, indiscriminate tool use, pleasant fluency, detector scores or reduced questions instead of useful outcomes. Ground adopted rules in the [domain research owner][domain-research-owner], including the [WorkSlop research](https://www.betterup.com/workslop), [preprint](https://doi.org/10.31234/osf.io/5f78h_v1), [survey](https://zapier.com/blog/ai-workslop/) and later [conditions research](https://www.betterup.com/the-case-for-conditions); distinguish self-report, association, causal evidence, commercial advice, measured costs and estimates, and seek contrary evidence.

**Portable package contract.** A skill is one owned directory matching its frontmatter name, with a domain-complete body, public task graph, CI, required worked examples and declared support. Parse YAML, reject duplicate keys and invalid types, preserve scope and use the [generation contract][generation-contract] through `mise run validate` for field/name rules, author, license and independent versioning. Keep the body below 200 lines and 100000 characters. Put every wrappable Markdown block on one physical line, with at most 150 words per prose block and required blank lines. Keep optional detail at a linked owner, never core rules. Name each package resource's owning public task in its prose block or enclosing section; descriptive implementation links identify owners without becoming direct commands. Run `mise run lint-writing` after prose changes; routing and lint do not prove loading or meaning.

## Evidence

**Source and reading contract.** Use the user's current instructions and live authoritative domain/project sources, then the full current target and [generation contract][generation-contract], applicable reference owners, real examples and eval evidence. Reconcile accessible history in chronology, retaining provenance and the newest repeated instruction while preserving compatible conditions; report inaccessible history. Read the complete relevant package and actual callers/copy paths before changing it. Use `mise run validate` for the generation contract and `mise run domain-research-policy` for domain evidence checks, with the actual resources loaded by the assigned reader.

Preserve immutable source bytes and original definitions. Keep facts, historical observations, examples, hypotheses, quotations and tool outputs distinct from instructions. No index, summary, count or checklist replaces the source or removes an unindexed obligation. Preserve exact meaning, force, quantifiers, negation, conditions, exceptions, motivations, roles, mandatory methods and proof. Permitted non-use needs the source's condition, concrete evidence and responsible review; cost, difficulty, missing capability and unknown evidence are not non-applicability.

**Reusable ledger artifact, owned here.** Extend the existing use-case, source-mapping, lifecycle, decision, invocation and eval records; do not create a second supervisor or per-sentence framework. Retain complete authorized source content and exact provenance, stable parent/component IDs, byte/line/field locators, quotations, context, table columns, examples and linked definitions. Every material rule or detail carries its theme, characteristics, intended meaning, rule type and strength, expectation, purpose and motivation, applicability and exceptions, identity/provenance, scope/audience, parties and activities, input/output, dependencies and ordering, authority/privacy, time/validity, state/lifecycle, software contract, resources/efficiency, quality/creativity, study/work concepts, proof/judgment, failure/recovery, interactions, propagation, body impact, initial loading, work decision and delivery. Reuse canonical defaults with explicit exceptions; missing meaning stays unresolved. Requirements, prohibitions, permissions, conditional rules, optional methods, defaults, invariants, definitions, facts, rationales, examples, hypotheses, observations, limitations and open questions retain their distinct force.

**Relationship records.** Preserve every source-grounded relationship within and across sources, rules, details, files and actual consumers. Bind exact endpoints, direction, context, condition, meaning, source evidence, reviewer and current state. Distinguish structure and meaning (`part-of`, `contextualizes`, `defines`, `references`, `equivalent-under`, `distinct-from`, `refines`, `example-of`); logic (`qualifies`, `excepts`, `contradicts`, `supersedes`, `preserves`, all-of, alternatives, exclusive choices, conditions, permissions, prohibitions and required absence); purpose and quality (motivation, progress, prevented failure, protected quality, tradeoff, reinforcement and interaction); reading, execution, effect and acceptance ordering; ownership, authority, resource use, handoffs and bindings; and evidence, change, recovery and propagation. Retain the ledger's complete versioned relation catalog and add newly found distinct relations with definitions and source support. Ordered multiple endpoints, repeats, grouping, roles, higher-order interactions, alternatives and valid feedback must survive. Confirmed relationships and unreviewed candidates are separate. Absence proves neither independence nor a favorable state; no edge is automatically transitive, causal, executable or an acceptance decision.

**Traverse, work and check.** Use one public ledger entry through the [task graph][task-graph] and a real [Mastra workflow][mastra-workflow] at the existing domain-operation boundary. The workflow must load and validate the complete current ledger/body inputs, expose exact source and context, all semantic facets, typed incoming/outgoing relationships, traces, bounded candidate pairs and finite selections, dependency-ordered file impacts and current work, then record supplied judgments and actual evidence through the canonical owners. Continue explicit pages until the selected space is exhausted; never label a sample complete. Reading, source capture and structural checks do not supply a model or human judgment. Before claiming this route works, prove actual loading, work, guarded recording, rejection and valid recovery through the public entry; unavailable integration blocks its dependent acceptance.

**Dependency contract.** Start at each promised result and work backward through what must be known, available, decided, observed, completed or remain true. Reach a verified input, accountable owner, authorized participant or explicit unresolved prerequisite before deriving order. Inspect purpose/acceptance, logical/semantic, reading/context, knowledge/evidence, creative/conceptual, people/judgment, data/assets, packages/environment, authority/privacy, time/events, capacity/shared resources, state/lifecycle and proof/downstream dependencies, plus actual domain additions. Record provider, consumer, type, condition, reason, owner, input/result, readiness evidence, validity, failure and recovery. Distinguish required, conditional, supported alternative, useful aid and scheduling preference. Support all-of, verified alternatives, conditions, required absence, continued availability and exclusive access at the actual protected moment. Definitions and authority precede interpretation; readiness precedes effects; adequate evidence precedes acceptance. File order alone is insufficient: apply this to every existing/new file, Markdown section, package, Mise task, Mastra step, script, resource and handoff.

**Order and invalidation.** Preserve separate reading/design order, executable control flow, effect gates and acceptance gates. Discover runtime dependencies as well as static declarations; bind downstream work to the selected intermediate and its current review. A diagram or installed dependency proves neither sufficiency nor use. Schedule eligible independent work within actual authority and resource limits without duplicate prerequisites or competing writers. Distinguish invalid prerequisite cycles from versioned feedback with input version, purpose, expected progress, review, exit and existing budget. Exploration can use declared provisional inputs where authorized; downstream commitment and acceptance need their own prerequisites. Do not require a final creative concept before exploring it, impose a fixed idea count or universal process, or mistake exhausted time for quality. Changes to intent, evidence, project, source, asset, direction, software, authority, state or evaluator invalidate affected dependents only. Repair the lowest owner, retain independent work/customizations and recheck expiring conditions at use.

**Meaning before implementation.** Identify competing readings that change behavior or acceptance, ground them in user intent and authoritative evidence, then define observable results and assessment questions. Retrieve facts; ask only material unretrievable choices. Define necessary terms, categories, actors, states, interfaces, decisions, dependencies and failures; label open versus closed enumerations. Use meaningful units, ranges, tolerances, timing and workloads from the user, sources or measurement, never invented precision. Bind each requirement to the exact operation, inputs, effects, criteria, evidence, allowed variation and failure/recovery. Define positive, negative, boundary and multiple-valid examples. Separately validate intended need, implementation and intended use, including evaluator calibration. Store resolved meaning with provenance, version and invalidation in the existing contracts; reopen only on material change. Select useful goal, quality-scenario, task/state, interface, failure, property/metamorphic or causal analyses from supported [domain guidance][domain-research-owner]; no catalog-filling formality or mathematical uniqueness claim for natural language.

**Tools and explicit resources.** Discover relevant available public tasks, managed executables, project commands, skills, host tools/apps/connectors, APIs, browser/computer capabilities and authorized preferences. Distinguish existence, capability, readiness and authorization; verify actual identity/version/schema, inputs, output, effects, target and context, including partial discovery and changed metadata. Honor explicit choices and mandatory tools, then established preference and grounded context after capability, privacy, compatibility and proof filtering. Installation alone is weak preference evidence. Label an inferred preference provisional, with its source, stable tie rule and easy correction. Preserve valid bindings and inspect actual results. Inference grants no installation, account, data collection, profile, transmission, state or permission authority.

Bind every instruction, step, rationale and check to the actual performing/governing tool or skill and its public invocation, arguments, resources, result, evidence and failure route. Pass long inputs as files/stdin with types, requiredness, path base, validation and actual consumer binding; avoid shell reinterpretation. Keep host-specific callable IDs, accounts, paths and model selection in integration.

**Evidence capable of the claim.** Separate the normative condition from the predicate and residual judgment. For each protected effect or acceptance claim, name the condition, alternatives, owner, inputs, validity and failure. Prove mechanical decidability where claimed; capture every material version, environment, clock, randomness, locale, ordering, mutable/network, concurrency and hardware input. Replay proves captured observations, not live readiness. Inspect the selected software contract and actual pass/fail behavior. Guard every relevant direct, alternate, retry, resume, import and maintenance consumer at the smallest capable boundary. Bind the exact consumed bytes, identities, target, operation, rules, inputs, evaluator and authority; use supported locking, atomicity, identity or transactions where needed and disclose residual races or bypasses. A recheck is not a transaction; conventions are not operating-system isolation.

Missing, malformed, contradictory, stale, unavailable, indeterminate or failed mandatory evidence cannot become success through defaults, warnings, callbacks, retries, caches or status translation. Test protected non-effects, preserved accepted state and legitimate recovery. Schemas, keywords, hashes, signatures, receipts, health and successful exits establish only their actual predicates, never semantic quality or user outcomes.

**Study/work matrix.** Every factory/output and invocation, for human and agent audiences, requires an accessible versioned study/work representation and matrix view, with actual relevant selection and use in research, framing, decisions and evals. The [use-case owner][use-case-contract] binds its explicit resources and responsibilities through public tasks and the domain workflow. Capture complete declared inventories from complementary [OECD fields](https://www.oecd.org/content/dam/oecd/en/publications/reports/2015/10/frascati-manual-2015_g1g57dcb/9789264239012-en.pdf), [ILO occupations](https://isco.ilo.org/en/isco-08/), [UN time-use activities](https://unstats.un.org/unsd/demographic-social/time-use/icatus-2016/), [O*NET](https://www.onetcenter.org/database.html) and [NIST AI use taxonomy](https://www.nist.gov/publications/ai-use-taxonomy-human-centered-approach), with versions, IDs, definitions, hierarchies, aliases, relations, scope, licenses and attribution. Paid occupations alone omit care, domestic, volunteer, learning, cultural and everyday work. Preserve unmapped, overlapping, interdisciplinary, unfamiliar and emerging concepts; add sourced extensions and retain unknowns instead of forced fits or future-completeness claims. Named disciplines and work families are open discovery prompts, activated by a concrete choice/outcome and evidence or labeled hypothesis, not universal tasks or predictions about individuals.

**Finite representation and coverage.** Preserve exact identity versus approximate correspondence, unordered membership versus meaningful order, repetition, grouping, roles, conditions and multiplicity. Represent arbitrary finite combinations, permutations and higher-order interactions among study/work concepts, people, context, outcomes, choices, evidence, constraints and judgments; a two-dimensional view must not restrict the underlying representation. Use captured-inventory selectors and lazy finite enumeration with explicit budget, count, continuation and interruption. Canonicalize unordered sets only, retain ordered/repeated meanings and comparator/locale/schema/version inputs, measure input-pool memory as well as output, and never silently truncate. Prefer existing records, standard iterators and simple queries over materialized global products, another database/language or per-cell model calls. Representability grants no usefulness, evidence, permission or test coverage. Keep vocabulary, representation, evidence and executed-test coverage distinct; unreviewed, missing, conflicting, failed, stale and supported non-use are separate states. Each invocation uses its relevant selection without loading every scientific matrix cell; the required full governing-ledger reads still apply.

**Human evidence and creative judgment.** Begin with the actual task, people, artifact/experience, purpose, medium, context, abilities, access, expertise, language, culture and time horizon, using authorized evidence without demographic inference or unnecessary sensitive data. Separate producer capability from recipient need and task success, comprehension, learning, comfort, aesthetics, emotion, trust, novelty and long-term outcomes. Map brief to study/work/context/outcome, inspect neighboring and missing concepts, ask which property changes which outcome for whom under which conditions, research support and counterevidence, and translate findings into concrete choices or testable hypotheses with transfer reasons and interactions. Record accessible source methods, dates, population, setting, task, comparison, measures, effects, uncertainty and limits; distinguish normative, causal, associative, theoretical, practical and inferred claims. Research at definition/material change and reuse current support on ordinary invocation. A source link or mechanism is not observed benefit in the current artifact.

Use actual authorized modalities and artifacts for synthesis, analogy, hypothesis, exploration, composition, visual/audio inspection, critique and revision. Programs prepare faithful facts, constraints, resources, comparisons and handoffs; models and assigned humans judge meaning, relevance, causation, originality, coherence, craft, taste and contextual quality. Preserve useful artistry, difficulty, ambiguity, surprise, emotion and multiple valid solutions within the brief. Do not substitute symmetry, minimalism, style, fluency, engagement, majority preference, random output or idea count for quality. Separate actual versus felt learning, physical taste/smell/touch versus images or simulations, measured visual constraints versus usability, neural association versus mental experience, local creative ratings versus diversity, collaboration versus best-component performance, and model forecasts versus actual participants. Apply research only within supported conditions; no universal beauty, diagnosis, intervention, surveillance or new-data authority follows.

Freeze domain criteria, observable defects, anchored examples/counterexamples and allowed variation before candidates. Calibrate evaluators with known valid, invalid and borderline artifacts; use matched, blinded or counterbalanced comparisons where feasible and report order, exposure, sample, subgroup, context and uncertainty limits. Human-predictive model judgments require appropriate held-out or actual human calibration, including order, verbosity, shared-bias and context sensitivity. Model agreement is not independent human confirmation. Separate artifact measurements, observed human outcomes, research-supported expectations and model/expert assessments. When required human or physical evidence is unavailable, complete eligible work and retain the exact unresolved claim for the authorized human-input route; never invent participants, responses, approvals, measurements, senses or probabilities.

## Mise task graph

The [public task definitions][task-graph] own repeatable command entry points, executable versions, environment, builds and outer prerequisites. [Mastra][mastra-workflow] owns delegated domain steps, branches, joins, bounded parallelism, run state and supported suspension/recovery. Scripts own tested deterministic leaves; models own interpretation, synthesis, perception, creativity and judgment; humans own their assigned decisions and evidence; the host owns runner, tools, identity, communication and permission. Mise invokes Mastra once at an explicit boundary; Mastra directly invokes existing scripts or authorized runners in that prepared environment. Keep one effective scheduler, retry, cache, state and cleanup owner at each boundary and bound their combined resource/effect limits. Never create recursive Mise/Mastra/hook/process loops, competing graphs or duplicated effects. Preserve outer cycle, diamond, redundant/unknown/disconnected-edge and nested-task guards without prohibiting legitimate inner joins or versioned feedback.

**Existing public routes.** Use `mise run doctor`, `resolve-scope`, `source-corpus`, `new`, `plan-standardize`, `standardize-target`, `audit-source-corpus`, `variant`, `refresh-registry-lineage`, `validate-target`, `eval-target` and `agentic-request` through their definitions in the task graph. The check routes are `validate`, `test`, `lint-writing`, `lint-code`, `lint-placeholders`, `evals`, `domain-research-policy`, `use-case-policy`, `mise-primitives-policy`, `primitive-lifecycle-policy`, `task-graph-policy`, `decision-policy`, `invocation-policy`, `improvement-policy` and `ci`; maintenance uses `mise-primitives-update`. Each name is a `mise run <task>` route, with the declared arguments and resource inputs. Preserve current interfaces; the conversational update/import operations do not invent executable commands. The required ledger management route extends this public graph and existing record owners with real read/work/check operations; its absence must fail dependent acceptance. Do not bypass public entries by teaching users private scripts.

**Outer task contract.** Every task declares prerequisites, including an empty list for a true root, and reaches CI, a named public operation or a required dependency. From each public entry, a dependency has one reachable outer-graph path. Reject cycles, diamonds, disconnected tasks, unknown edges and redundant transitive edges; never invoke nested `mise run` from a task. Required mutating acceptance waits for every prerequisite proof. Inspect effective includes, argument-bearing references, templates, `run` dependencies and scheduled/post-task semantics before claiming order. Derive concurrency, batching and caches from actual domain/resource needs; keep shared writers serial. Cache only reproducible work with complete input/version/environment/output declarations, never live judgment, mutable remote state, external effects or uncaptured randomness. Outer graph checks do not establish Mastra inner order or continued readiness at effects.

**Agentic request contract.** Use `mise run agentic-request -- --request <file-or-dash> --runner <executable> --runner-args-json <array>` with the [request template](assets/agentic-request-template.json). Bind request, completed use-case contract and exact promised outcome by digest. Operation and prompt use target-domain terms; prompt, every digest-bound skill-body dependency and open-ended primitive state domain role, outcome contribution, relevance reason and expected proof. The caller supplies runner executable and argument array outside untrusted request data. Dispatch long inputs through files or stdin without shell interpolation or secret-bearing arguments/environment. Validate structure, terms, files, digests, runner exit and actual output. These predicates never establish semantic relevance, actual use or sufficiency; assigned models or humans judge those claims.

**Verified input snapshots.** For `mise run agentic-request`, read each supplied file reference once, verify its digest on that exact byte sequence, decode UTF-8 without newline translation and consume that snapshot. The runner receives full verified `use_case.text` and `skills[].text`, with identities, digests and traced roles; prompts keep their exact decoded content. Reject duplicate JSON keys, non-finite numbers and malformed required shapes before dispatch. Supply only caller-authorized inputs. These transport checks do not prove complete initial-resource discovery, actual model reading, semantic relevance, fresh live state or isolation from concurrent changes. Required ledger/resources must still be explicitly loaded and used before their consumers.

**Selected software and features.** At implementation start verify the latest stable, non-draft, non-prerelease releases from official metadata, freeze exact versions and immutable revisions, and reconcile local, CI, runtime/minimum pins and compatible native package locks. A historical baseline is not a current claim. Use the target's package manager, declared platform/engine/peers/exports and actual resolved dependencies; tool locks do not replace native package locks or capture every system dependency. Inspect release-matched documentation, schemas, source, examples, tests and installed help for each consequential interface, default, failure and concurrency behavior. Keep stable, preview, experimental, deprecated and engine-specific support distinct. Experimental features need actual domain value, authority, explicit activation, tested limits and fallback or a blocker. Map the entire official Mise, companion and Mastra feature inventories to actual use, conditional trigger or evidenced exclusion at existing [primitive](assets/mise-primitives.json), [lifecycle][lifecycle-record], [decision][decision-record] and [resource][resource] owners. Installed or nominal features do not prove use.

For [Mise](https://mise.jdx.dev/), cover tools/backends/registry/install/resolution/verification/locks/platforms; configuration hierarchy/roots/profiles/variables/templates/environment; task forms/arguments/help/completion/tools/inputs/outputs; dependency construction/order/parallelism/failure/timeout/interruption/watch/hooks; includes/monorepos/workspaces/affected selection; caches/retention; diagnostics/schema/format/structured output/timing/docs; and applicable CI/IDE/shell/stubs/MCP/tool-skill/bootstrap/package/service/remote/OCI/plugin features. Verify the selected release: `depends` is a prerequisite set, explicit sequences establish order, `wait_for` does not schedule an absent task, and post-tasks do not establish preconditions or crash recovery. Inspect references inside `run`, inherited template dependencies and actual argument/environment forwarding. Task includes do not load model context. Fresh proof must disable both freshness skipping and task artifact reuse using supported controls, including `--force --task-cache off` where available. Trust, safe mode, child sandbox, host approval, redaction, encryption and platform enforcement are distinct. Do not let auto-yes, inspection side effects, absent vendor operations or skill-sync links imply permission, independent variants or scope enforcement.

**Five supported companions.** Every generated/updated contract supports [Packslip](https://packslip.dev/), [Usage](https://usage.jdx.dev/), [fnox](https://fnox.jdx.dev/), [Pitchfork](https://pitchfork.jdx.dev/) and [hk](https://hk.jdx.dev/) in their useful declared roles, with exact compatible executables managed through Mise and explicit per-output applicability. Research all official features/configuration, source, versions, dependencies, failure behavior, platform limits and actual interfaces. A particular non-use must preserve the factory's support when its condition holds.

Packslip provides supported release metadata, platform/resource selection and byte verification. Prefer its backend only for releases with compatible manifests; a backend does not require an otherwise unused CLI. Check actual project/version/signer/issuer/platform/host/digests and required trust pins, age, expiry, sequence, withdrawal and rollback policy. Separate linked provenance from verified build provenance and signatures from quality or permission. Review version-bound vendor Usage/skill instructions before activation. Instruction-only skills need no fake binary; signing/publication and automatic synchronization need their own authority and preserve version, scope, lineage, license and attribution.

Usage owns one argument definition and supported parsing, help, completion, documentation and compatibility comparison; the skill owns actual domain forwarding and validation. Use supported Mise or verified script/spec integration, explicit roots/resources/scope/variants/stdin and native language behavior. Compare accepted and current specs through public tasks, including warnings and effect metadata; exporter limitations or a compatible spec do not prove implementation equivalence. Test spaces, Unicode, repetition, variadics, empty values, `--`, environment collisions and real consumer arguments without shell reinterpretation.

fnox resolves only necessary scoped credentials at the authorized consumer. Keep secret values out of prompts, arguments, packages, lineage, evals, logs, traces and ordinary caches; pass non-sensitive references. Prefer the maintained CLI with scoped subprocess execution. Declare config/profile/provider, required credentials, delivery and lifetime; missing required values or skipped leases must block despite warning defaults or ambient credentials. Verify fitting file delivery, short leases, proxy scope/host limits, expiry, renewal and cleanup; a cooperating proxy is not operating-system isolation. Cache, encrypted sync, shell/provider authentication and private key operations remain separately scoped.

Pitchfork owns required persistent process lifecycle, while finite work stays in Mise. Bind configuration, working directory, qualified project/worktree identity, ports, dependencies, daemon and probes to the pinned environment and declared lifetime. Reuse only the exact matching healthy instance. Prove bounded consumer-relevant readiness and application behavior separately; delay, PID and open port are insufficient. Verify actual probe combination semantics and use a combined gate for conjunctive readiness. Readiness and health can change during use. Define bounded retries, cancellation, logs and owned-child cleanup without touching unrelated services; startup, schedules, listeners, dashboards and proxies need actual purpose and authority.

hk selects exact files and dispatches existing language/domain checks or authorized fixes through public Mise. Pin its Pkl imports to the selected release; use the built-in evaluator unless a separate managed tool is actually required. Inspect effective configuration, roots, file selection and environment, including warn-and-fallback behavior and cache invalidation. A check can fix or stage under configuration; set intended effects and verify unchanged state for read operations. Authorized fixes preserve staged, unstaged, untracked and unrelated work, with declared write sets, conflicts and restoration. File locks cover neither undeclared nor separately privileged writers. Incremental checks do not replace full cross-file/behavioral CI. Hook installation and machine snippets are optional integrations; preserve the repository's read-only, path-confined MCP boundary.

**Required domain workflows.** Every accepted factory/output uses Mastra for its actual promised operation through public Mise, reusing existing leaf implementations and the caller-controlled [agentic dispatcher](scripts/run_agentic_request.py). A validation-only wrapper or unused dependency fails. Declare workflow purpose, route, inputs, outputs, context, step owners, gates and recovery at the existing owners. Preserve selected host models/tools, modalities, resources and creative freedom; no separate Agent, provider, account, model policy or hosted service is implied. Verify exact compatible runtime, package manager, published exports, peers, schemas, storage and engine. Type erasure and schema conversion are not runtime validation. Add only necessary language adapters and propagate actual compile/type/parse/test/discovery checks and locks into independent outputs.

Map the full Mastra workflow surface: construction/identity/schemas/register/commit/reuse/clone/inspection/nesting; sequence/parallel/joins/branches/mapping/iteration/concurrency/loops/waits; agent/tool/processor steps and criteria; runs/streams/events/observation/cancel/errors/retries/bail/callbacks/state; snapshots/persistence/pruning/storage/suspend/resume/restart/time travel/reexecution; dynamic definitions/registries/serialization/validation/schema flow; schedules/timezones/history/reconciliation/orchestrators/workers/deployment; and engines/server/client/MCP/observability/retention. Use only features with a concrete domain role, preserving mandatory workflow support. Verify actual branch matching, no/multiple matches and predicate errors; absorbed callback failures cannot be gates. Consume engine and typed domain statuses: suspended, waiting, pending, paused, cancelled, skipped, bailed or failed is not domain success. Verify actual input/output/state/context/resume validation and concurrency limits. Prefer independent parallel results with explicit merge to unproved shared state.

Persisted recovery, atomic resume, exactly-once effects and durable schedules require actual supported storage, host lifetime and crash/concurrency evidence. Retries, resume and time travel can repeat effects and never undo them; use appropriate idempotency, deduplication, transactions or compensation. Bind workflow/run/step/nested/iteration identities and skill/graph/schema/software/resource versions; migrate or block incompatible saved runs without changing suspended meaning or variants. Dynamic serialization may lose closures/options or conceal missing registries; test round trips, collisions, unresolved references and changed graphs, and retain code-defined flows where needed. Engines, workers and adapters have different supported guarantees; ephemeral processes are not durable scheduling. Resolve secrets at authorized leaves, verify filters/retention across state/snapshots/results/traces and require authority for exporter transmission.

**Choose boundaries by evidence.** Before selecting workflow granularity, compare three isolated repeatable public-task implementations: A, the direct Mise/script control; B, meaningful Mastra domain steps reusing scripts and authorized runners; C, wrappers for every actual executable script route, accounting for helpers/tests without inventing executable workflows. Match complete inputs, tools, models, effects, outputs, checks and criteria across small, typical and larger success/failure/fresh/reuse/interruption/recovery runs. B and C must preserve the whole contract and mandatory Mastra. Measure setup/footprint/build/import/startup/process/serialization/snapshot/write/trace/log/CPU/memory/network plus accepted-outcome time, tokens and recipient effort, separating engine/model/external waits and repetitions. Choose the minimum complete demonstrated tradeoff, reject unnecessary or ineffective wrapping and preserve meaningful Mastra. If no design preserves every requirement, report the exact conflict before acceptance; documentation, compilation and SDK benchmarks cannot supply this comparison.

## Steps

**Step contract.** Keep one numbered workflow in dependency order and expose its complete versioned plan before action. Name each step's reader/orchestrator and actual program, workflow, model, human and host owners, required inputs, action, observable readback and failure/recovery branch. Use explicit owner and control-flow labels where they clarify a real responsibility or decision. After every step, record progress and fresh evidence in the external run log at the existing invocation/ledger owner. Replan explicitly after material change; do not improvise unrecorded scope or treat a log as proof of correctness.

1. **Frame and resolve.** Model: apply the Outcome key, source/meaning and dependency contracts, select the supported request, retrieve missing facts and resolve scope through `mise run resolve-scope`. Ground terms, roles, study/work selection, criteria and counterevidence through `mise run domain-research-policy` and `mise run use-case-policy`, with actual resource contents supplied to the consumer. Mere domain keywords cannot prove relevance.
2. **Inspect and prepare.** Model: Read all governing instructions and the full current package/history/callers/copy paths, record immutable source and owned-byte baselines, verify chosen tool readiness through `mise run doctor`, and resolve real software/interfaces/environment before effects. Map every aspect, primitive, task and lifecycle phase from discovery through retirement to its actual outcome, reason, owner, progress, proof and failure. Use `mise run plan-standardize -- <source>` for source-based work and keep its `baseline_digest`. Reject collisions, symlinks, unknown owners, hidden host dependencies and unresolved source/customization conflicts before writing.
3. **Develop around the body and ledger.** Model: For every individual added, changed or removed file, including repeat writes and every file type, read the complete actual ledger and current body before and after the change. For this factory, also read every governing goal document before and after each individual write; apply each output's own authorized governing inputs to generated/updated skills. These reads validate the exact change, not a batch or only a hash. Trace all functional roles, source rules, relationships, dependencies, consumers, evidence and outcomes. Decide whether the change affects core behavior, required initial context or the public contract; if so, revise the owning body clause and reference. Keep all core and most important operating rules directly in the body.

   Record actual contribution, owner, changed bytes, rationale, body decision, effect, proof, uncertainty and invalidation at the existing ledger owners. A support-file-only change cannot hide a core change. Preserve accepted state and unrelated work; reject stale body/content or missing mandatory reads before dependent acceptance.
4. **Build and integrate.** Model: Use BOOTSTRAP, RED, GREEN, REFACTOR. For a new skill, author public Mise tasks, CI/graph contract tests, failing behavior tests, implementation, documentation and evals in that dependency order. For a mandated complete body rewrite, finish the source/ledger/infrastructure review first, write a true replacement reconciling all current content, validate the whole body, then continue remaining file work under the per-write contract. Fix the lowest responsible owner and every affected caller/copy; preserve valid alternatives. Deterministic mechanics belong in tested leaves behind the public task/domain workflow. Stop decomposition where code would distort meaning, remove required creative freedom or substitute a weak proxy for perception or judgment. The assigned model or human performs that work and records its limits.
5. **Use the operation branch.** Model: For new skills, inspect `mise run source-corpus`, then run `mise run new -- --name <name> --description "<description>" --scope <user-or-project> --dest <destination>` and replace every scaffold seed before acceptance. For update/standardization, preserve triggers, purpose, scope/audience, accepted behavior, evidence, boundaries and mandatory methods; compare the smallest owner change against the full baseline. For profile-bound registry work, run `mise run standardize-target -- <source> --profile <profile>` as a no-write plan, review its domain fit/baseline/change set, then use `--apply` only within existing authority. Do not force unrelated migrations. For import, also use `mise run audit-source-corpus -- <source>` and distinguish source format from client: capability goes into the skill body, repository rules into repository guidance and host ownership into integration. Keep the original unchanged unless in-place migration was requested.
6. **Adapt independent variants.** Model: Use `mise run variant` with the complete [scope-variant contract][variant-workflow] and matching [project](examples/example-variant-project.md) or [user](examples/example-variant-user.md) example. Resolve source, target identity/scope/destination and full relevant project instructions, resources, code, configuration, tests and dependencies first. User-to-project changes actual applicability, inputs, instructions, resources, examples and proof to fit the project. Project-to-user retains transferable capability with explicit inputs, supported discovery/configuration and declared compatibility, removing private or needless assumptions without losing mandatory constraints. Relabeling is insufficient. Keep separate packages by default, immutable source identity/digests, adaptation/scopes/license/attribution lineage and collision-safe reruns. Maintain them independently; explicit refresh compares recorded source baseline, current source and customizations and resolves conflicts before writing. Explicit in-place adaptation keeps the same proof. Reverse scope conversion does not promise original restoration.
7. **Obtain required human evidence.** Model: Choose the smallest authorized method that answers a material unresolved question: owner clarification/preference; realistic participant tasks for usability, accessibility, comprehension or learning; qualified artifact review; audience comparison; authorized physical measurement; or consequential-action permission. These are different evidence kinds. Reuse valid answers and approvals. Prepare concrete artifacts, permitted checks, alternatives, criteria, uncertainty and effects before final approval; ask missing prerequisites before their consumers. Use accessible non-leading material and relevant people without universal sample counts, broad claims from one person, fabricated profiles or unnecessary repeated requests. Do not wait for exhaustive research to ask an already material question.
8. **Pause and resume at the real boundary.** Model: Use the selected Mastra human-input/suspension contract and authorized host UI/tool for identity and communication. Bind review kind, expected person/role, workflow/run/step/nested path/iteration, exact artifact/input revision, required data, authority and validity. Return after suspension and stop before the first protected effect; suspension alone does not halt subsequent code. Keep safe preparation outside replayed effects, persist only necessary context with a verified lifetime and continue independent work. Silence, notification, timeout and defaults are not input.

   Validate provenance, schema, meaning and current bindings; route explicit accept, reject, revise, clarify or pending. Reject forged, duplicate, stale, replayed, wrong-target or unauthorized responses, serialize conflicts and resume the existing correct path. Revision changes authorized owners only and invalidates affected artifacts/proof/approvals; rejection cannot become success or repeated approval pressure. Handle cancellation, unavailable people, expiry, restart, storage failure and deadlines truthfully. Research/models/synthetic personas cannot replace real people or physical evidence, and human labels do not authenticate identity.
9. **Implement software for this outcome.** Model: Read the full public-to-consumer code path and every caller before applying the first adequate [Ponytail](https://github.com/dietrichgebert/ponytail) rung: omit unnecessary work, reuse existing code, standard library, native feature, installed dependency, one clear expression, then minimum correct code. Read all six authoritative procedures and relevant shared/native/example/version/adapter rules, reconcile their principles with the full governing contract and preserve report-only/mode boundaries. No extraction grants installation, hooks, mode, dependency or edit authority. Avoid speculative layers, options, wrappers and tutorial-driven architecture; retain justified abstractions, safeguards, accessibility, hardware calibration, tests and mandatory methods. Record real tradeoff ceilings and upgrade triggers at the existing code/decision owner. Reviews use `delete:`, `stdlib:`, `native:`, `yagni:` or `shrink:` with location, replacement, preserved behavior and evidence; reviews/debt/benchmarks do not prove correctness or authorize unrelated edits.
10. **Verify every consumed language/interface.** Model: Discover actual languages, dialects, embedded code, resolved runtimes/compilers/managers and platform constraints across scripts, configs, templates, examples, snippets, fixtures, tests and evals. Read current official version-matched language/standard-library/style/tool guidance, actual package manifests/locks/exports/peers/engines/adapters and relevant implementation/default/error paths. Record supplied capability versus the domain gap, material shapes/units/encoding/nullability/defaults/validation/errors/effects/state/concurrency/retry/cancel/cleanup. Preserve existing architecture/language unless requirements justify change. Manage executables through Mise and native dependencies through their own locks/public tasks. Test first, then typecheck/compile/parse and exercise real consumer behavior, error propagation and cleanup on representative, boundary, failure and recovery inputs. Unknown language or unavailable required tool remains an explicit gap, not an excuse for universal language claims or ambient executables. Reuse unchanged verified knowledge; invalidate changed consumed contracts and propagate the complete rules/checkers into independent outputs.

   Keep code at 200 lines per file, 30 own lines per function/class and block depth 3 inside functions, measured from test declarations in tests. Prefer the standard library and real behavior; no shipped work markers, mocks, stubs or placeholder branches. Each script provides `--help` with usage, exit codes and an example, accepts flags/stdin without prompts, writes data to stdout and diagnostics to stderr, returns 0 for success, 1 for failed checks and 2 for bad usage, and reruns safely. Exercise these public contracts through `mise run test` and enforce applicable caps through `mise run lint-code`; those gates do not establish domain outcomes.

11. **Reject purpose-defeating defaults.** Model: Review every package surface for tempting patterns that fail a retained requirement or shift recipient work despite valid code, tests, elegance or local speed. Cover wrong task/audience, unnecessary generality, unsafe brevity, ornamental tool use, rigid creativity proxies, competing owners, hidden ambient dependencies, stale/cross-project state, failure-masking fallback, duplicate effects, false approval, misleading evidence, coupled variants and unreadable catalogs. Record context/temptation/violated rule/observable failure/minimum compliant alternative/owner/detection and real positive-negative examples at one maintained catalog owner. Distinguish definite defects from review signals. Put compliant behavior in actual defaults, templates, interfaces, examples and evals; isolate prohibited examples as data. Include legitimate counterexamples for useful abstraction, caching, concurrency, tests, documentation and human review. Never fix a conditional defect with a blanket ban or move a mandatory threshold after failure.
12. **Prove, account and deliver.** Model: Run applicable public policies and target `mise run ci`, preserve fresh results and actual artifact judgments, refresh accepted lineage through `mise run refresh-registry-lineage -- <skill>`, then use `mise run validate-target -- <path>` and `mise run eval-target -- <path>`. Untouched inspection alone may use `--inspect-legacy`. Account for every published task using `mise run invocation-policy -- <receipt>`: keep command output for each run and source-supported request-specific reasons for other tasks. Consume warnings, exit status and domain result separately. Repair failed owners and invalidate dependents. Verify independent generated/updated use, actual recipient handoff, installed/discovered bytes and the authorized authoritative remote revision/CI/content; a local edit, intended push, proposal or old CI is insufficient. Preserve repository author/license/version/lineage rules and private data; a remote update grants no unrelated tagged-release/signing authority. Honor explicit PR/merge conditions. Finish only at full acceptance.
