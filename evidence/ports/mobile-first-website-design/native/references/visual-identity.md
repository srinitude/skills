# Visual identity

Backlink: [SKILL.md](../SKILL.md). Load only after a valid `wireframe_sha256` exists.

Visual identity is separate from structure. It may not silently reorder sections, remove proof, weaken the primary action, or change semantic focus order.

## Inputs

Use the frozen brief, approved wireframe hash, brand assets, audience characteristics, content requirements, and selected reference mechanisms.

## Three directions

Create exactly three identity directions. Each direction defines:

- one audience-specific visual premise
- palette roles with contrast targets
- type roles, size ranges, and loading plan
- image language and treatment
- icon and illustration behavior
- surface, border, radius, and elevation behavior
- texture or decorative motif, if justified
- logo usage
- motion thesis in one sentence

Avoid default dashboard motifs, arbitrary gradients, interchangeable geometric decoration, and generic marketing-photo treatment. Every choice needs a stated audience or content reason.

## Score and freeze

Score distinctiveness, audience fit, message support, accessibility, system coherence, asset feasibility, and responsive behavior from `0..5`. Choose the highest total; break ties by stable ID byte order. Run external and native judgement. Freeze the approved token and asset-direction bytes by SHA-256.

## Smallest-to-largest styling

Style the smallest breakpoint first. At each larger width, add only space, columns, scale, or peripheral detail that preserves the frozen obligations. Record changes or `UNCHANGED`. Revalidate contrast, crop, hierarchy, and action visibility before advancing.
