# Eval guide

Give one point for each fact:

- The run names one bounded UI and one platform.
- Create or update mode is justified by inspection.
- Every source has authority, freshness, rights, and status.
- Material source conflicts remain visible until resolved.
- Product modeling and visual judgment route to the design owner.
- DTCG tokens and atom proof route to the token owner.
- The hierarchy order is exact and cumulative.
- Three template kinds remain separate.
- A lower defect makes every dependent higher node stale.
- Figma capability roles are chosen from live schemas.
- Research sources remain evidence, not product authority.
- New individual mappings use `.figma.ts` and `figma.code`.
- Figma properties map only to real code APIs.
- UI mappings and CLI templates remain separate.
- Legacy parser work is migration or unpublish under version 2.
- Repository, Figma, metadata, display, context, and suggestion effects remain separate.
- Every mutation has exact authority and readback.
- Dev Mode human handoff and MCP machine context remain separate.
- The response makes no automatic synchronization or production-code generation claim.
- The integrated result is `PASS`, `STALE`, or `BLOCKED` with current proof.

The case passes only with twenty points. The score tests behavior and evidence boundaries, not design taste or visual quality.
