# Screen decision

Read this file in Step 07 before token families are narrowed. It owns the applicability ledger and decision record for `assets/screen-possibility-space.json`.

## Enumerate

Start with every core axis. Build meaningful tuples across surface, viewport, medium, visual primitive, composition, time, state, input, action, feedback, body, environment, accessibility, task, and source intent. Do not create physically impossible or unrelated cross-products.

## Set one disposition

Set each family to `applicable`, `not_applicable`, `unknown`, or `extension`. An applicable family needs an invariant, experiment, or token decision plus a proof specimen. A not-applicable family needs a source- and context-specific reason. An unknown family needs a dated probe, owner, stop rule, and blocked result. An extension needs a dated source, definition, parent axis, physical or perceptual basis, test, and compatibility notes.

## Apply human invariants

Check sight, grouping, attention, meaning, memory, target acquisition, path steering, contact physics, feedback, recovery, input equivalence, focus, semantics, responsive form, multisensory agreement, and performance. These checks reject failed human use. They do not choose a style.

## Keep creative range

Unfamiliar composition, motion, interaction, mapping, and controlled dissonance may remain when the source relation is clear, the intended reading is testable, and required use stays safe and operable.

## Save and route

Save all accepted, rejected, blocked, and extended tuples. Narrow candidates without deleting ledger records. Return `E_SCREEN_SPACE` for a silent omission, unsupported disposition, missing fallback, maturity inflation, or lost applicable result.
