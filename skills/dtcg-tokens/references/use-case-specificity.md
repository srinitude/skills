# DTCG token use-case specificity

Load this reference through \`mise run domain-research-policy\` before changing DTCG token domain terms, roles, evidence, lifecycle owners, or task purposes.

## Outcome

Keep every DTCG token package primitive tied to source-specific token generation, material experiment evidence, standalone rendered proof, or package acceptance. Generic skill boilerplate fails even when its file shape is valid.

## Research questions

The machine contract in \`assets/use-case-contract.json\` is loaded through \`mise run domain-research-policy\`. It must ask one current question for every actor, object, action, state, invariant, variant, interface, authority, failure, recovery, evidence, time, resource, quality, terminology, and exclusion dimension.

Use at least four current web sources across two hosts and two source classes. Prefer the published DTCG format for token structure, WCAG for measurable accessibility constraints, current Mise documentation for task mechanics, and the Agent Skills specification for package shape. Record limitations and counterevidence. A source can constrain one claim without proving token quality.

## Hyper-specificity test

For every DTCG token skill body, reference, asset, deterministic implementation, test, Mise task, example, eval, policy, schema, and record, state its role, protected outcome, motivation, progress value, prevented failure, and proof through \`mise run use-case-policy\`.

Reject a primitive when replacing “DTCG token” with an unrelated domain leaves its text and behavior true. Reject a primitive that exists only to fill a package slot. Reject a Mise task that does not produce token progress, evidence, a bounded failure, restoration, or lifecycle control.

## Factory update owner

Every DTCG token package mutation begins with the current skill-factory \`mise run plan-standardize -- /absolute/path/to/dtcg-tokens\` baseline. After local DTCG checks, the factory must run \`mise run validate-target -- /absolute/path/to/dtcg-tokens\`, \`mise run eval-target -- /absolute/path/to/dtcg-tokens\`, and \`mise run invocation-policy -- <receipt>\`. This preserves the token skill's purpose while enforcing one update method.

## Judgment boundary

DTCG token structure, task topology, hashes, state transitions, coverage, and receipt completeness belong to Mise. Source interpretation, material experiment design, visual authorship, taste, originality, restraint, human eye, brain, touch, and current-pixel acceptance remain model-owned. Human authority owns purpose changes, destructive evidence removal, publication, and deployment.

A deterministic pass cannot replace visual judgment. A visually pleasing render cannot override invalid token structure, accessibility constraints, false source claims, or missing authority.
