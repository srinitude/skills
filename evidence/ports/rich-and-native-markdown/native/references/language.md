# Preserve meaning before polishing

- Load and apply `human-language` and `meaning-preserving-rewrite` before substantive work. Both are required at every stage and in every invocation.

## Purpose and reading route

- **Reading trigger:** Read before any wording or meaning decision and before each output check.
- **Prerequisites:** No other package file must be loaded first. Required companion skills must already be active.

### Preserve each source clause

- Use the full meaning-preserving-rewrite process for rewrites within its stated scope.
- Capture the live source and required backup, build its clause ledger, and map every source requirement to its final wording and location.
- Keep the ledger current after edits or file splits.

- Preserve actors, actions, scope, order, conditions, exceptions, negation, and requirement strength.
- Keep facts, numbers, units, names, quotes, citations, paths, commands, code, and other exact data intact.
- For input outside that skill's scope, still compare source and output for meaning loss without forcing an unrelated policy-rewrite process onto it.

## Keep both skills active throughout

- Read [input and output coverage](coverage.md) before intake or transformation. Check all supplied data and every invocation result, as well as the skill package.

- Apply both skills during source intake, context loading, research, primitive selection, dependency planning, drafting, splitting, moves, validation, repairs, handoffs, and delivery.
- Before each stage, identify the reader, purpose, source meanings, protected exact text, and the rules that apply.
- Before each save or send, check meaning and language at word, phrase, sentence, section, file, and cross-file levels. No internal or temporary text is exempt. A short label needs a short check.
- Include headings, list items, labels, alt text, captions, table cells, metadata prose, examples, tool-call prose, reports, and handoffs.
- Map new user rules explicitly. Do not pass off new assumptions as source meaning.
- If either skill or needed context cannot be loaded, stop the affected work and name the missing source. Do not substitute a copy, bypass a check, or claim it ran.
- Review every editable word, phrase, sentence, line, section, file, and connection between files.
- Reload either skill if its rules leave context; constant application does not require a tool call for each word.

### Cover the package and all results

- This duty covers two complete sets: the skill package itself, during creation, each invocation, and every later change; and all outputs created, changed, or returned at each invocation, in any format.
- For the skill package, include SKILL.md, reference files, the full primitive catalog, examples, templates, usage text, and all other editable prose.
- For outputs, include the entry file and every child, shared reference, appendix, note, caption, table cell, link label, image description, and other editable text.
- Prose inside an example or code fence still needs review when it is being authored; protect exact code, data, and quoted text.

- Use both live skills at every stage. Constant application does not require repeated retrieval when complete, current rules remain available.
- Keep exact source material unchanged; apply language checks to its explanations and meaning checks to its placement and interpretation.
- Before drafting, name the reader, purpose, needed context, and next action.
- During each edit or file split, check the changed text and its surrounding meaning before saving or sending it.
- When joining work, apply the same checks to the joined result.
- A skill reference, earlier successful check, or clean word scan does not prove that later text is clear.

### Write plain, exact text

- Aim for U.S. grade 6 or below in editable English prose.
- Use plain adult language, clear actions, and a natural voice.
- Remove filler, hype, vague claims, needless repetition, and stock AI phrasing.
- Preserve the author's stance and useful detail.
- Never invent facts, sources, feelings, or personal stories.

- Keep required exact text and technical syntax intact.
- Explain hard terms in plain words where allowed.
- Use a fitting reading-level tool when available, plus a full human-language review.
- Never claim a measured grade without a real measurement or sacrifice meaning to improve a score.

- If a fitting reading-level check scores editable prose above grade 6, revise that prose and check it again.
- Review hard passages on their own; a low average cannot excuse them.
- Keep any exception limited to exact or required specialist text, state why it must stay, and explain it in plain words where allowed.
- If no fitting tool is available, review the prose by hand and report no measured grade.
- A score or detector result cannot prove clarity, human authorship, or reader understanding.

### Review cross-file meaning

- Check how the files work together, not only how each sentence reads.
- Use steady names for shared ideas.
- Make each file's purpose, prerequisites, reading triggers, and next step clear.
- Follow links in the intended reading order.
- Check that definitions arrive before they are needed, conditions stay with their actions, and moved detail remains easy to find.
- Fix unclear references such as "this" or "above" when a split changes their meaning.
- Remove needless repeated explanations without deleting required context or a useful reminder.
- Do not make readers assemble a rule from scattered fragments.

- Keep both Markdown source and its supported rendered view readable.
- Choose spacing and structure for the content.
- In the skill's catalog files, give each entry's How, When, Where, Why, syntax, source, and limits room to read; do not preserve a dense layout merely because the supplied catalog uses compact entries.
- Splitting or reformatting must preserve all entries and their meaning.
- Rich formatting and short files do not excuse unclear prose or broken reading order.

## Require both final reviews before delivery

- After all drafting, edits, file splits, and joins are complete, review the entire finished skill package before accepting its creation or update.
- At the end of every invocation, review both the current complete skill package and the entire output set, including Markdown and non-Markdown results, before delivery.
- Review all editable text, every file, and the connections among files.
- Do not replace this final review with samples, checks of changed lines, or earlier passes.
- Reuse still-valid supporting checks and complete source text already in context where allowed, but assess the final complete text and file relationships.
- Full review does not require fetching an unchanged file again when its complete current text is still available.

- Keep a brief record of the files and final versions reviewed, exact text excluded from rewriting, checks actually run, faults found, and repairs made.
- For a large set, read in bounded passes and track full coverage without loading everything at once.
- Then check the joined whole for meaning, facts, reading ease, voice, and fit.
- The coverage record supports this review; it does not replace reading the content.

- Use meaning-preserving-rewrite to confirm that language repairs kept every applicable meaning and requirement.
- Use logic-audit to check the final text and cross-file reading paths for conflicts, missing context, unclear duties, and unsupported claims.
- Resolve faults, repeat affected checks, and finish with another whole-set review.
- Any later edit reopens review of the changed file and its affected readers or references, followed by the whole-set check before delivery.

- Do not accept or deliver a result as complete while an applicable language check fails or required text remains unread.
- Keep the specific fault or missing coverage open and state the limit plainly.
- Acceptance requires both the skill package and each invocation's full output set, including Markdown and non-Markdown results, to pass their applicable final reviews.
- Report only checks actually performed; do not call this review real reader testing unless that testing took place.
