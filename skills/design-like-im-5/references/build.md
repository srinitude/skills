# Build the product

Load this file before pipeline steps 5 and 6.

## Goal

Build the full product from proved low parts. Keep its main use easy to see, know, and do.

## Atom work

Find the skill named `dtcg-tokens`. Use its full current process. Do not replace any of its work with this file.

Record every token and atom run link. Each kept atom needs a seen sample and a passing review.

## Part order

Build atoms first. Then build molecules, organisms, templates, screens, and flows. List each direct part link in the chain file.

Each part must state its use, main user aim, seen choices, needed facts, response, error path, and simpler valid option.

Each part must also name the context-derived states it can enter, leave, or change. Do not force unrelated parts into one state name. Keep composite, short-lived, and unknown states visible in the chain.

Make one focus-intent record for each token, atom, molecule, organism, UI composition template, screen, flow, and transition. Use these fields:

- Task and target: `user_task`, `focus_target`.
- Place and time: `focus_location`, `focus_timing`.
- Method and cause: `focus_mechanism`, `focus_reason`.
- Order and rivals: `attention_sequence`, `competing_signals`.
- Exit and failed proof: `defocus_and_recovery`, `failure_evidence`.

Say what the person should see and where it is. Say when it should gain or lose weight. Show how the design makes that happen. Tie the reason to the task or risk. Name what comes first, next, later, or at the same time. One focal target is not a fixed rule. Two targets need a reason and a clear order, unless they must be seen at once. Test the target against its strongest rival in whole views, clear details, screen sizes, states, and real input paths. Reject focus that is an accident, comes at the wrong time, traps the eye, or ignores the task. A filled record is not proof, and prominence alone is not intent.

When a screen needs a new low part, stop the screen. Prove the low part first. Mark each linked high part stale. Rebuild and review those parts.

Across all kept high parts, use each kept low part once. Add a proved exclusion when a part should stay unused.

## Open design

Make unlike options before one choice. Include a true reverse idea when it fits. Reject only with a found veto or a failed product aim.

Use product facts to shape style and action. Do not copy the face of a source. Do not make all media look the same.

Keep four unlike starts as a floor, not a ceiling. Add, split, mix, or reverse them when the product calls for it. The model chooses. A script only checks fields and vetoes.

Before keeping a part, run its objective failure, bad design, and bad practice checks. Reject text or image collisions that hide needed meaning. Reject clipped work, covered controls, target clashes, and dead ends.

Trace each output claim to current proof. Do not call code, a schema, or a filled record proof of good sight, thought, touch, use, or value.

Test contrast, spacing, hierarchy, and identity in whole views, readable details, responsive sequences, and real input paths. For spacing, distinguish related-item gaps, insets, group separation, section rhythm, shell separation, readable measure, gutters, and target separation. A numeric scale is not visual proof. Reject uniform spacing that erases grouping, unexplained emptiness, crowding, and distinctive gestures that break access or familiar control behavior.

At each artifact checkpoint, compare the retained work with a familiar default and at least one materially unlike alternative. Keep a difference only when it expresses product meaning and survives changed content, viewport, state, and input. Mark the affected higher parts stale after any lower-owner change.

Use `references/controlled-comparisons.md` through `mise run test` before retaining each item. Give every state, atom, molecule, organism, UI composition template, screen, flow, and transition one current pair at its lowest owner. Link the pair to a real option and a test record frozen before sight. For a part relationship, vary one role while holding its siblings and every non-tested token fixed. Do not bundle several changes into one comparison.
