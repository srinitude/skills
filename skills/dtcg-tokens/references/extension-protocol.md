# Extension protocol

Use this reference when the source, intent, token need, visual language, interaction, review finding, or experiment is not named by an existing catalog. No catalog is a ceiling. The catalogs define the minimum search surface and the evidence shape for adding new material.

## Fixed core

Keep the 25-step order, named input-output handoffs, DTCG rules, evidence fields, state transitions, PASS and BLOCKED gates, claim limits, and final visual readback fixed. These contracts make two runs comparable and keep customization auditable.

## Open surface

Allow any inspectable input, intent, token family, DTCG extension, qualitative lens, defect marker, perceptual or motor invariant, experimental strategy, comparison method, specimen form, interaction, layout, visual language, copy structure, and source-specific proof experience. Add only what the current source or task supports. Do not choose from a menu when a new source-specific form explains the system better.

## Add one extension

1. Name the extension in plain language and give it a stable local ID under the matching catalog namespace.
2. Classify it as an input, intent, token, lens, defect, invariant, experiment, or another explicitly named local class.
3. Cite the source locator, task clause, observed condition, or tested hypothesis that requires it.
4. Define its value shape, applicability, interaction with existing entries, downstream records, and proof method.
5. Add it to the relevant possibility ledger before narrowing; record included, excluded, experimental, or not-applicable status with a reason.
6. Route its output through `assets/execution-io-map.json`, validate it with the same gate as its nearest class, and expose it in the evidence and proof artifact when retained. Use `mise run token-packet -- <args>` for this routed resource.

## Customization boundary

Customize the token system and standalone HTML as far as the source supports. Do not customize away DTCG conformance, evidence lineage, perceptual or motor safety in claimed use, exact input-output accounting, or truthful claim limits. A new extension may add a better path; it may not bypass a failed gate. When two custom forms both satisfy the evidence, preserve both readings until the source, audience, or task provides a reason to choose.
