## Scope And Limits

The research question is: which established findings, current standards, recent papers, and emerging technologies should change how the skill generates, tests, and reports source-specific DTCG tokens?

No finite search can inspect every arXiv record, technology, standard, framework, or physical display. The current method uses broad, reproducible query families across creativity, originality, visual judgment, recognition, multimodal interaction, HCI, accessibility, graphics, display systems, touch, haptics, spatial computing, and agent orchestration. It stops after required coverage passes and consecutive additions stop changing mechanisms, risks, tests, or token decisions. This appendix records a dated basis, not an eternal claim of exhaustiveness.

## Evidence Classes

| Class | Allowed use |
| --- | --- |
| Final standard or stable official report | Conformance or stable baseline, within stated scope. |
| Peer-reviewed primary research | Design rule when method and task transfer are supported. |
| Current preprint | Experiment proposal or warning; not the only basis for a stable rule. |
| Active standards draft | Technology-watch candidate; maturity and support remain explicit. |
| Official implementation or compatibility record | Availability evidence for the named environment only. |
| Secondary synthesis | Search lead or corroboration; primary source still required for a decisive claim. |

Search snippets never become evidence. Every runtime research record must save the query, URL, publisher, publication date, retrieval date, source class, version, extracted mechanism, counterevidence, and access limit.

## Token Format Baseline

The [Design Tokens Format Module 2025.10](https://www.designtokens.org/tr/2025.10/format/) is the pinned output contract. It is a stable Community Group report dated 28 October 2025, not a W3C Standard. The skill must keep its conformance claims at that exact level and must recheck the latest published version before any current-version claim.

## Font Selection Baseline

The [Google Fonts Developer API](https://developers.google.com/fonts/docs/developer_api) can return the current catalog sorted by popularity. Each run uses that same-date order, excludes the most popular half, and saves the response date, rank boundary, candidates, and selected families. The [Google Fonts repository](https://github.com/google/fonts) supplies family files and license records. Rank does not prove source fit. Three eligible uncommon candidates still need strong-vision comparison, license capture, self-contained embedding, byte hashes, and offline proof.

## Creativity And Idea Generation

| Sources | Retained consequence |
| --- | --- |
| [Standard definition of creativity](https://doi.org/10.1080/10400419.2012.650092), [ideation metrics](https://people.it.tamu.edu/~stevesmith/SmithCreativity/ShahVargas-HernandezSmith2002.pdf), and [creative product scales](https://doi.org/10.1080/10400418909534323) | Test novelty, appropriateness, resolution, and synthesis separately. Fluency alone is insufficient. |
| [Atypical combinations and impact](https://pubmed.ncbi.nlm.nih.gov/24159044/) | Pair unusual relations with enough conventional grounding to remain legible and useful. Maximum difference is not the goal. |
| [Creativity types](https://pubmed.ncbi.nlm.nih.gov/26280076/) | Require combinational, exploratory, and transformational lanes rather than one generation method. |
| [HypoSpace](https://arxiv.org/abs/2510.15614) | Separate validity, nonredundancy, and coverage so a correct but collapsed candidate set cannot pass. |
| [CreativityPrism](https://arxiv.org/abs/2510.20091) and [task-specific creativity evaluation](https://arxiv.org/abs/2606.11762) | Keep quality, novelty, diversity, and fulfillment task-specific. Do not infer broad creativity from one test. |
| [Human diversity and collective creativity](https://arxiv.org/abs/2607.26899) | Treat simulated viewpoint variety as a search aid, not proof that the candidate pool matches human diversity. |

These findings justify the typed exploration corpus, four candidate lanes, generation before evaluation, quality-diversity retention, and separate vetoes.

## Originality, Identity, And Visual Judgment

| Sources | Retained consequence |
| --- | --- |
| [Human Creativity Benchmark](https://arxiv.org/abs/2606.30561) | Preserve agreement on defects and meaningful disagreement on taste or conceptual risk. A single score loses information. |
| [Visual Aesthetic Benchmark](https://arxiv.org/abs/2605.12684) | Prefer matched comparative sets over isolated scalar ratings. Current automated judgment is not expert consensus. |
| [Visual-judge bias study](https://arxiv.org/abs/2606.29672) | Counter bias toward polish, edge density, and generated finish. Complexity cannot stand in for originality. |
| [AesEval-Bench](https://arxiv.org/abs/2603.01083) | Require region selection and located defect or quality evidence, not global prose. |
| [MuseBench](https://arxiv.org/abs/2606.30026) and [CreBench](https://arxiv.org/abs/2511.13626) | Judge relationships across visual, audio, narrative, process, and product rather than object recognition alone. |
| [DreamSim](https://arxiv.org/abs/2306.09344) and [LPIPS](https://richzhang.github.io/PerceptualSimilarity/) | Compare multiple levels of appearance, layout, pose, semantics, and relation. No single distance metric proves uniqueness. |
| [Image memorability](https://pubmed.ncbi.nlm.nih.gov/26353315/), [organization and memorability](https://pmc.ncbi.nlm.nih.gov/articles/PMC6696787/), and [memorability review](https://pmc.ncbi.nlm.nih.gov/articles/PMC8818973/) | Keep memorability separate, context-relative, and measured with hit and false-alarm evidence. |
| [Open-set recognition](https://arxiv.org/abs/2403.16528), [open-set baseline](https://arxiv.org/abs/2110.06207), and [multimodal retrieval](https://arxiv.org/abs/2606.04240) | Test matched distractors, top-k retrieval, confusion, transformations, and `none of the above`. |
| [Brand element ownership study](https://doi.org/10.1057/S41262-020-00187-6) | Distinctive elements must both differ from competitors and support recognition. Difference alone is insufficient. |
| [Stylometry](https://arxiv.org/abs/2507.00838), [audio fingerprints](https://arxiv.org/abs/2410.21876), and [tactile identity](https://arxiv.org/abs/2606.31451) | Use modality-specific signatures and degradation tests. Style cannot prove authorship. |

These findings justify separate claims for source specificity, source originality, output originality, identifiability, corpus uniqueness, memorability, provenance, and bounded one-of-a-kind status. Global uniqueness remains unsupported.

## Perception, Graphics, And Physical Interaction

| Sources | Retained consequence |
| --- | --- |
| [CSS Snapshot 2026](https://www.w3.org/TR/css-2026/) and [SVG 2](https://www.w3.org/TR/SVG2/) | Treat layout, text, color, paint, shape, transform, mask, filter, composition, animation, and viewport behavior as explicit families. Stability varies by module. |
| [Pointer Events](https://www.w3.org/TR/pointerevents/) | Record pointer type, pressure, tilt, twist, contact geometry, capture, cancel, coalesced events, predictions, and direct-manipulation policy where applicable. |
| [Media Queries Level 5](https://www.w3.org/TR/mediaqueries-5/) | Test pointer and hover quality, gamut, dynamic range, viewport segments, forced colors, contrast, reduced motion, reduced transparency, theme, and data preferences. |
| [Device Posture](https://www.w3.org/TR/device-posture/) and [Screen Orientation](https://www.w3.org/TR/screen-orientation/) | Make hinges, seams, posture, writing direction, safe regions, and fixed-orientation accessibility part of responsive decisions. |
| [WebXR Device API](https://www.w3.org/TR/webxr/) and [Hand Input](https://www.w3.org/TR/webxr-hand-input-1/) | Extend screen reasoning to gaze, tracked pointers, articulated hands, three- and six-degree movement, field of view, depth, and world-relative interaction. |
| [WCAG 2.2](https://www.w3.org/TR/WCAG22/) and [WAI-ARIA 1.2](https://www.w3.org/TR/wai-aria/) | Keep stable minimums for semantics, keyboard use, focus, contrast, reflow, target size, drag alternatives, orientation, motion, timing, and flash safety. |
| [WCAG 3 draft](https://www.w3.org/TR/wcag-3.0/) and [WAI-ARIA 1.3 draft](https://www.w3.org/TR/wai-aria-1.3/) | Monitor broader emerging scope, but do not replace stable WCAG 2.2 or ARIA 1.2 claims with draft language. |
| [Fitts target-acquisition study](https://doi.org/10.1037/h0055392), [Steering Law](https://doi.org/10.1145/258549.258760), and [one-handed target study](https://doi.org/10.1145/1152215.1152260) | Test distance, size, path width, path length, posture, and error instead of enforcing one universal target number. |
| [Perceived input point study](https://www.patrickbaudisch.com/publications/2010-HolzBaudisch-CHI10-TheGeneralizedPerceivedInputPointModelAndRidgePad.pdf) | Treat touch error as dependent on posture, person, and three-dimensional contact, not only fingertip width. |
| [Feature integration](https://doi.org/10.1016/0010-0285%2880%2990005-5) and [graphical perception](https://doi.org/10.1080/01621459.1984.10478080) | Test feature conjunctions, attention, and data encodings rather than relying on salience or decoration. |
| [Crossmodal correspondence review](https://pubmed.ncbi.nlm.nih.gov/21264748/) | Test semantic and temporal agreement across senses, plus deliberate dissonance, rather than assuming any multimodal pairing works. |

These sources justify the screen possibility tuple, applicability ledger, human and physical vetoes, and direct inspection of actual rendered and interactive states.

## Deterministic Execution And Visual Reasoning

| Sources | Retained consequence |
| --- | --- |
| [Lost in the Middle](https://arxiv.org/abs/2307.03172) | Keep decisive rules beside the action that uses them. Load short step-local records instead of relying on distant material in a long context. |
| [Instruction hierarchy failure study](https://arxiv.org/abs/2502.15851) | Freeze authority, fixed constraints, forbidden actions, and conflict handling before execution. Stop rather than silently choose between unresolved rules. |
| [PlanBench evaluation](https://arxiv.org/abs/2409.13373) and [planning benchmark suite](https://arxiv.org/abs/2406.13094) | Save the plan as state transitions. Check preconditions before each action and effects after each save. Do not treat fluent prose as a valid plan. |
| [Compositional generalization scaling study](https://arxiv.org/abs/2205.12253) | Use constrained schemas, intermediate records, held-out combinations, and exact parsing. More general skill does not guarantee correct new combinations. |
| [CorrectBench](https://arxiv.org/abs/2510.16062) | Separate authoring, self-check, external evidence, and final adjudication. A second pass is not proof unless it tests a saved predicate. |
| [VisuLogic](https://arxiv.org/abs/2504.15279) | Probe spatial, positional, attribute, quantitative, stylistic, and state-change reasoning. Record regions and relationships. Do not accept captions or generic reasoning text as visual proof. |
| [R-Bench](https://arxiv.org/abs/2406.16449) and [SpatialEval](https://arxiv.org/abs/2406.14852) | Test inter-element relations and make the visual path inspect pixels before using text. Use structured evidence as support, not a vision substitute. |
| [OSR-Bench](https://arxiv.org/abs/2505.11907) | Use negative samples, non-existent distractors, spatial records, and separate perception from later decisions. |
| [OSWorld](https://arxiv.org/abs/2404.07972) | Inspect high-detail screenshots, test layout variation and state history, and treat click or target precision as a separate failure source. |

These findings do not justify naming execution tiers in the skill. They are converted into short steps, typed records, local constraints, negative controls, held-out cases, separate review roles, and fail-closed vision rules. The skill may mention an AI model only in the strong-vision gate and its required delegation or blocked result.

## Counterevidence And Limits

- Novelty can reduce fit, clarity, accessibility, or trust. It never compensates for a veto.
- More candidates can increase redundancy. Coverage and nonredundancy both need checks.
- Memorability may reward unusual or emotionally salient content without proving originality or source identity.
- Perceptual similarity metrics disagree across low-level appearance, layout, semantics, and crossmodal relations.
- Current visual judges can prefer polish and complexity. Sparse or unfinished input requires explicit bias controls.
- Research prototypes often use small samples, controlled hardware, or narrow tasks. Their reported effects do not transfer automatically.
- Standards drafts can change. Stable conformance claims must remain tied to final documents and verified support.
- Crossmodal effects can be person-, culture-, context-, timing-, and device-dependent.
- Parallel research broadens search but increases cost, duplicate findings, and integration risk.

## Refresh Protocol

Every run acquires one current date anchor, checks the pinned token standard, searches current primary sources for active technology candidates, and records retrieval dates and versions. Refresh the corpus manifest when a new source changes an axis, mechanism, risk, test, maturity class, or token decision. If current evidence is inaccessible, stale, contradictory, or unsupported, keep the affected claim or technology `BLOCKED` rather than guessing.
