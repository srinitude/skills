# Failure and repair

Load this file when a gate fails, a rule is old, sources clash, or a low part changes.

## Reply shape

Start with `BLOCKED` or `STALE`. Name the gate. Name the proof that exists. Name the gap and linked parts. Give the smallest safe action that can resume work.

## Common states

- `SOURCE_GAP`: A needed page or file cannot be read.
- `VISION_GAP`: A pixel claim has no strong visual check.
- `RULES_OLD`: A dated rule passed its refresh point.
- `LAYER_SKIP`: A high part added a new low rule.
- `STALE_DEP`: A low change broke a high proof.
- `VETO`: Safety, access, sense, or agency failed.
- `OBJECTIVE_FAILURE`: Direct proof shows a collision, lost cue, blocked action, state clash, or dead end.
- `HARM_CHECK`: A bad design, bad output, or bad practice item failed.
- `CHECK_MEANING`: A check was skipped, swapped, scored, or read outside its fixed meaning.

Do not retry the same failed path three times. Check the facts and use a new safe path. Keep work that does not depend on the gap.

## Recovery

Get the missing right, fact, source, tool, low part, render, input trace, record, or test. Rebuild all linked parts. Run visual review and all changed checks again.
