# Human matrix format

Read references/use-case-specificity.md through `mise run domain-research-policy` for the required domain and human-outcome contract. Load this format through `mise run human-matrix` when preparing or consuming explicit matrix resources and selections.

## Resource inputs

Bind all five source captures explicitly. The resource file contains integer `version: 1` and a `resources` object keyed by every catalog identifier. Each value supplies `path` and `sha256`; paths are absolute or relative to that binding file. The reader checks captured bytes against the package's registry, parses each complete declared hierarchy, rejects missing parents, duplicate identifiers and cycles, then resolves selections. Use real paths without symlink ancestors. A current-data URL is not an immutable snapshot. Keep raw inventories outside portable packages when redistribution is not authorized; distribute the required reader and declared access route. Independently usable output must not require the factory installation, its private paths or credentials.

Run `mise run human-matrix -- --resources <bindings.json> --matrix <case.json> --matrix-sha256 <digest>` with actual inputs. The declared Mastra workflow first resolves the complete inventories and then consumes the bound matrix and its records, checking the current implementation and inventory bindings. For vocabulary inspection, the same task accepts `--concepts <JSON-array>` instead of a matrix; it preserves the supplied order and repeats. Lookup alone cannot replace required contextual use or the skill's separate promised domain workflow. A workflow result remains unaccepted until the existing evidence owner consumes its actual evidence and responsible judgments.

## Matrix records and identity

Use JSON schema version 1 with `comparator: unicode-codepoint` and `locale: und`. Object keys and collections of records identified by `id` are semantically unordered. Identifiers use letters, digits, `.`, `_`, `:`, `/` or `-` and start with a letter or digit. Labels and other text retain their Unicode content. The public result binds both the original matrix bytes and its canonical serialization. Do not compare only a display or sorted flat list.

| Matrix field | Meaning and mechanical boundary |
| --- | --- |
| `records` | An object of named references to existing domain, research, decision, dependency and evaluation owners. Each supplies `path`, `sha256` and a nonempty `pointer` array of JSON keys or integer indices. Relative paths resolve from the matrix file. Consume the selected content from the bound file; the reference is not evidence that its claim is true. |
| `extensions` | Records with `id`, `label`, `definition`, `aliases`, `state` and `source`. IDs start with `extension:` and remain distinct from catalog IDs. A named extension needs a definition. An unresolved extension may retain null. Its source supplies a bound `record`, `version`, readable `url` or null, `locator`, `scope` and `license`. Preserve unresolved meaning rather than force an incorrect classification. |
| `correspondences` | Addressable records with `id`, `from`, `to`, `relation` and a bound `judgment` reference. Supported distinctions are `exact_match`, `close_match`, `broader`, `narrower` and `related`. These are declared concept relationships, not workflow order, causal proof or automatic identity substitution. Aliases never silently resolve to another identifier. Source hierarchies remain separately accessible through each concept's parent records. |
| `occurrences` | Records with `id`, exact `concept`, domain `role` and `conditions` referencing bound records. Different occurrence IDs preserve repeated practice or activity instances even when the concept is identical. |
| `groups` | Records with `id`, `semantics` and `members` referencing occurrences or groups. Ordered groups retain their sequence. Unordered groups sort membership for canonical serialization without removing repeats. Groups may nest or share members; reject identity collisions and containment cycles. |
| `interactions` | Records with `id`, `study`, `work`, `people`, `context`, `outcomes`, `choices`, `evidence`, `constraints`, `judgments`, `dependencies` and `state`. Study and work refer to selections; the other arrays reference bound domain records. They retain a relationship involving several fields, activities, people, constraints and choices. The matrix view links its study/work selections back to the complete interaction ID. Never replace that interaction with independent pairwise claims. |
| `selectors` | Addressable finite spaces with `id`, `operator`, `pools`, `length`, `conditions`, `role` and `semantics`. Each pool supplies either ordered exact `ids`, preserving repeats, or a complete `catalog` sorted by the declared comparator. Resolve every concept against captured resources before returning the symbolic space. |

Use the relationship distinctions in the [SKOS Recommendation](https://www.w3.org/TR/2009/REC-skos-reference-20090818/). An approximate mapping is not exact identity. A concept collection is not a new concept. Source identity, a correspondence judgment and its evidence remain independently addressable; no RDF store or ontology service is required.

The dependency references extend existing use-case, decision, resource and workflow records. Preserve each provider and consumer, type, activation condition, rationale, owner, required result, readiness evidence, validity and recovery. Distinguish all-required prerequisites, verified alternatives, conditional branches, absence, exclusivity, continuing availability and completion order. Use partial order and legitimate parallel work where supported. For feedback, bind successive input versions, intended progress, review, exit and budget. Do not turn a semantic relationship or valid inner Mastra join into an outer Mise diamond, cycle, second scheduler or duplicate effect. A bound JSON dependency record does not prove scheduling or readiness.

Keep vocabulary coverage, representational coverage, evidence coverage and executed-test coverage separate. The reader validates selected structures and complete declared inventories. It does not evaluate science, taste, human response or domain test coverage. Unknown relationships stay unknown; conflicting evidence is not missing evidence. Use the meanings and invalidation rules in references/evidence-acceptance.md through `mise run invocation-policy`. A model must not convert a missing review into a favorable verdict. Changed inputs or judgments reopen affected relationships while preserving unrelated evidence.

## Finite spaces and execution budgets

Use the actual [Python combinatorial iterators](https://docs.python.org/3.13/library/itertools.html): `combinations`, `combinations_with_replacement`, `permutations` and `product`. For the first three, `length` is the selected tuple length and there is one pool. For `product`, it is the repeat count for the complete ordered pool sequence; tuple width equals the number of pools multiplied by that count. Combination groups are unordered; permutation and product groups are ordered. Native iteration follows pool order and distinguishes positions, including equal values at different positions. Retain source versions, pool identity and comparator when comparing results.

A symbolic selector describes its complete finite space without constructing the cross-product or claiming that its members are relevant, allowed, researched or tested. Every concrete result uses the same occurrence/group records, with an address binding the original canonical matrix, selector, pool digest and rank. Preserve that address and positional provenance in the existing evidence records when using a member later. A different input, grouping, order, multiplicity or context can change identity. Canonicalize only the structures declared unordered.

To enumerate one entire space, add `--enumerate <selector-id> --max-members <count> --max-output-bytes <bytes> --max-memory-bytes <bytes> --max-seconds <seconds>` to `mise run human-matrix`. Counts are decimal integers; seconds may contain a decimal fraction. Every budget is explicit. The iterator is lazy, but its input pools and the bounded returned result use memory. The output reports pool memory, traced allocation peak, tracer overhead, elapsed time, runtime and budgets. Counts, measured memory, elapsed time and final serialized output are checked before any result is emitted. A budget failure returns no partial successful result. Enumeration does not perform the represented activities or satisfy their permissions.

The memory budget covers Python allocations traced from the second step's source resolution plus tracer metadata. It is not total process RSS, the earlier inventory step, the Mastra host, npm setup or an operating-system hard limit. Checks observe allocations and use preflight bounds; they cannot prevent every transient allocation. Use a separately verified host limit if the domain requires that stronger guarantee. Measure the whole public path separately for performance claims. A killed query has no accepted result; a new query must use the same current bindings or record their change. Do not report sampling, truncation or an interrupted attempt as exhaustive coverage.
