# Product design fit

Load this note through `mise run domain-research-policy`. Do this before you change design terms, roles, states, proof, or what stays out.

## Outcome

This skill makes a full digital product clear and easy to use. It keeps the product true, known, fresh, and safe under change. It does not make mere pretty screens or stock UX tips. A set of passed files is not design proof.

## Evidence basis

Use current product facts first. Use [WCAG 2.2](https://www.w3.org/TR/WCAG22/) through `mise run domain-research-policy` for access rules. Use [Apple access help](https://developer.apple.com/design/human-interface-guidelines/accessibility) through the same task for size, space, sense, and motor needs. Use [Apple focus help](https://developer.apple.com/design/human-interface-guidelines/focus-and-selection/) through the same task to keep focus and saved state apart. Use [GOV.UK space help](https://design-system.service.gov.uk/styles/spacing/) through the same task for space roles. These sources set bounds. They do not prove fit, fresh work, or good sight.

Run `mise run domain-research-policy` to check source dates, scope, hosts, and proof against each claim. [The use case file](../assets/use-case-contract.json) is read through that task. The model reads each source. It judges if the source backs the saved claim. A valid receipt cannot make that choice.

## Domain map

Map people, things, acts, states, rules, forms, links, rights, faults, fixes, proof, time, means, quality, terms, and bounds. Add a product part only if it can change an act, proof, fix, or pass.

Design states may mix, nest, clash, change in use, or stay unknown. A closed list is a prompt. It is not proof that all states were found.

The human eye judges first sight, groups, contrast, move, and change. The human brain judges truth, sense, recall, cause, risk, and repair. Human touch judges size, gaps, reach, input, reply, work, and error repair. The same sight owner views fresh pixels. Fixed checks may reject a result. They cannot grant visual PASS.

## Product-design primitive map

Run `mise run use-case-policy` to check each skill part. It checks bodies, notes, files, code, tests, tasks, cases, rules, forms, and proof. [The use case file](../assets/use-case-contract.json) is read through that task. Each part must name its design role, aim, cause, value, stopped fault, and proof.

Swap the design terms for a new field. If the skill still makes sense, fix its first stock owner. Then remove the design terms. If it still claims a full pass, its design use is gone.

## Boundaries

Mise owns steps, state moves, forms, order, receipts, and checks that can run twice. The model owns source sense, cause, new choices, design judgment, and direct sense review. People own product intent and high cost rights. One owner cannot act as another.

This skill can run alone for product design. A Figma or Code Connect flow may call it as one owner. Figma tools, maps, and project proof stay out of this skill.
