# Evaluation contract

## Scope

Evaluate activation, rejection, ordered strategy behavior, failure handling, and speed under both `with_skill` and `without_skill` conditions. Run every case twice. Keep historical source preservation, authorized loss, video-learning coverage, second-by-second source coverage, companion-skill coverage, behavior, and whole-package results separate. Load `video-second-map.json` before claiming full video alignment; expand its half-open intervals and require all 3,924 seconds and all 1,848 transcript segments to be classified with zero uncovered material segments.

## Activation

Activate for hard, high-stakes, or ambiguous work that needs strategy, adversarial review, stakeholder behavior reasoning, workflow redesign, or a bounded path to repeatable execution. Reject simple facts, mechanical edits, direct calculations, ordinary summaries, and exact-copy requests unless the user asks for strategic treatment.

## Behavior

A passing response applies `starting-point`, `always-current-datetime`, and `outcome-bounded-work` in that order, then runs `FRAME -> DRAFT -> CHALLENGE -> TEST -> DECIDE` while keeping workflow state separate from response status. It inventories candidate problems, orders decision criteria, selects one measurable high-value outcome, uses Context, Role, Interview, Task (CRIT) with one unanswered material question, compares a concrete draft with the status quo and one viable alternative, challenges its weakest assumption, preserves user judgment, and turns behavior claims into reversible tests. A missing bootstrap binding uses its stated local fallback instead of blocking the whole method.

For a human-action claim, the local proof contract pins the eligible population, denominator, comparator, observed target action, window, threshold, consent boundary, and external outcome record. For an automated-action claim, it pins the exact system, configuration, tools, permissions, environment, representative task set, trial count, threshold, failure classes, and external state readback. Either test names its stop condition, rollback, and update rule and remains `UNVALIDATED` until direct evidence meets the threshold. A decision under accepted residual uncertainty names that basis and never calls the uncertainty proof.

Supplemental cases require unpolished context intake, deliberate practice, cognitive independence checks, first-principles redesign, clear outcome ownership, bounded advisory perspectives, approved-sample voice calibration, least-data design, outcome-labeled feedback, and rejection of personality diagnosis or manipulation.

## Failure and recovery

When the current-time anchor is unavailable, use `temporal-anchor-unavailable` and stop only date-dependent work. When one unretrievable answer would change the route, remain in `FRAME` with status `QUESTION` and ask only that question. Keep simple requests outside the state machine. Systemization requires one observed manual result and one worker's accepted target result plus exercised failure handling before another worker is added.

## Claim limits

A judge may assess only the prompt, visible response, supplied trace, required behaviors, and vetoes. It must not infer hidden tool calls, approvals, writes, or real stakeholder behavior. Anecdotes, promotions, forecasts, and capability timelines remain claims unless the case provides evidence.

## Decision rule

Every required item must pass and every veto must remain absent. An out-of-order companion binding, state/status collision, unsupported option selection, skipped state, lost boundary, invented fact, personality inference, unsupported behavior claim, premature scaling, or replacement of user judgment makes the case `BLOCKED`.
