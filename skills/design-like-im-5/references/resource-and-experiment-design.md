# Product-design resources and experiments

Load this reference through `mise run improvement-policy` before changing product-design experiments, task order, cache policy, data shape, timing, or the skill itself.

## Material product experiments

Run a large design test before you accept any design layer. Test tokens, atoms, molecules, organisms, templates, screens, flows, and moves. Make the pair easy to tell apart. Change the task, order, state, act, shape, work, or repair. Do not use a needed pass on a tiny polish change. A small fix for a seen fault is not pure polish.

Set the test before you view either choice. Freeze the user scene, state, text, view, input path, low locks, claim, null, change, test, and rule. Hold all else still. One link may move more than one value only if one design owner owns them.

Use [references/controlled-comparisons.md](controlled-comparisons.md) through `mise run run-packet` for the comparison record. Direct human eye, human brain, and human touch judgment chooses, rejects, or blocks the result. Metrics and structure can veto a candidate but cannot rank taste or grant visual PASS.

Acceptance locks the selected owner and closes that branch. A new requirement, contradictory current vision, accessibility failure, runtime mismatch, missing state, or recorded falsifier can reopen it. Reopening a lower owner marks every dependent design and proof stale.

## Speed without lost proof

The speed goal is time to a fully proved design result. Run safe read checks at once. Change one owner at a time. Start slow source and render work early. Use the first check that can reject a path. A fast partial result is not progress.

Cache only deterministic work whose full inputs, runtime version, environment, outputs, and invalidators are declared. Never cache live web state, model judgment, direct vision, human approval, or a side effect. A cache hit is reused computation, not current product evidence.

Use maps to find a saved record. Use sets for checks that repeat. Add proof to an ordered log. Stream a large file once. Use digests to mark old work. Replace one passed owner as one safe write. Add a harder form only if a timed design block shows a real gain.

## Resource checks

For a design skill trial, check time, CPU, RAM, disk, and web use. Check cache, context, starts, shared work, cost, and human care too. Mark an unfit check with proof. Keep a measure only if it can change the choice.

## Optional skill improvement

Run `mise run improvement-policy` against [assets/improvement-contract.json](../assets/improvement-contract.json) after required product work passes. Freeze the last accepted digest, evaluator, inputs, environment, time budget, repetitions, and resource dispositions. Change one named dimension at the smallest owner.

Keep the change only if its named part gets much better. Truth, time, task fit, safety, reach, and token use must not get worse. New ideas, tests, sight, care, plain words, and all rules must not get worse. If one gets worse, restore the last passed digest. Then run its small proof again.
