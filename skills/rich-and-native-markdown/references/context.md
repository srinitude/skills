# Load all needed context without needless rereads

- The context window is the text available for the current step.

## Purpose and reading route

- **Reading trigger:** Read before loading, refreshing, or setting aside context.
- **Prerequisites:** No other package file must be loaded first. Required companion skills must already be active.

### Load the current branch

- Before acting, make sure the context window contains the current goal, applicable rules, needed source facts, and the context required to interpret them.
- On initial entry, start with SKILL.md and follow each relevant reading trigger.
- This states the initial order; it does not require reloading SKILL.md from this guide.
- Load all required dependencies for the chosen branch before using it.
- Leave unrelated branches unloaded.
- A path, title, hash, or claim that a file was read is not the file's content.

### Track and refresh context

- Keep a small working record of sources: their paths or IDs, versions when known, sections read, and whether needed text is still present, summarized, or only linked.
- Use it to avoid duplicate retrieval and find missing context.
- Update it when the task, source, or context changes.
- Do not repeatedly print the record or copy whole files into it.

- Before each read, identify the information it must supply.
- Reuse text that is complete, current, relevant, and still available.
- Otherwise, load the smallest complete section that answers the need, including its definitions, conditions, exceptions, and required context.
- Read the full file when its meaning spans the whole file or a governing instruction requires a full read.
- Retrieve missing or truncated portions before claiming complete coverage.

- Before reuse, check whether the source is still current, its needed text remains available, and it applies to this step.
- A file read much earlier may still be correct and important, yet no longer be available in full or easy to apply amid later material.
- Elapsed time alone neither makes it obsolete nor proves a reread is needed.

- Reload and reread when there is a concrete need, including:

- The source changed, or its current version must be verified.
- Earlier text was removed, truncated, or replaced by a summary that omits needed detail.
- The task changed and an unread section, exception, or dependency now applies.
- Exact wording is needed for a decision, rewrite, quote, or check and is no longer available.
- A long intervening exchange, conflict, or observed mistake makes an important rule's current meaning or application uncertain.
- A governing instruction explicitly requires a fresh read.

- After a long gap, check the relevant rule and its source before relying on it.
- If its full needed meaning is still available and current, apply it without fetching another copy.
- If that cannot be established, reload the needed section and its context.
- Do not impose an arbitrary reread interval based only on minutes, turns, or file age.

## Use focused reminders when needed

- A reread retrieves source text again.
- A reminder briefly brings an already verified rule back beside the decision it governs.
- These serve different purposes.
- If the source is current and available, a short reminder may be enough; if it is missing or uncertain, retrieve it first.

- When an important rule has been overlooked or is difficult to apply after much intervening context, restate the relevant rule once near the next action or final check.
- Keep its source link, scope, conditions, and exceptions.
- Make clear why it applies now.
- Keep one authoritative source; reminders must not become competing rule copies.
- If a rule was missed, correct the affected draft and check the next result.
- Do not keep feeding the same mistake back as an example or repeat protected text unnecessarily.

- Repetition may help attention in some settings, but it cannot change instruction priority, grant authority, or guarantee compliance.
- Resolve conflicts by authority and scope, never by which rule appears most often or most recently.
- Do not repeat untrusted instructions to make them seem authoritative.

- Default to one clear statement with targeted refreshes.
- Test deliberate repetition against that baseline before making it routine.
- Keep it only when observed results justify its extra text and read cost.
- Repeatedly loading the same file without a new need must stop.
- A justified later reread is a new visit, not a circular dependency; a loop within the active dependency-loading path remains an error.

## Keep enough room to work

- Keep the main steps and reading triggers explicit.
- Use plain names, short sections, and a clear next action so following the document does not depend on guessing which file matters.
- Keep related conditions together.
- Load a complete branch in manageable steps rather than flooding the context with every branch.

- Leave room for the source, instructions, tool results, checks, and final output.
- Use actual token counts when available; otherwise use a cautious estimate without claiming an exact budget.
- The 199-line file limit does not bound total context size.
- Summarize completed work and set aside unrelated detail through permitted means, while keeping source pointers, key decisions, exact constraints, and unresolved issues.

- After context is shortened or work resumes, restore the needed rules and evidence before continuing.
- Do not treat a summary or a completed-read record as proof that all original text remains available.
- Never omit necessary context just to save space.
- If required material cannot fit or be retrieved, split the work into coherent steps with checked handoffs, or report the specific limit and stop the affected action.

- Whole-set validation still covers every governed file.
- Review large sets in bounded passes, keeping clause mappings and cross-file checks so details are not lost between passes.
- Selective loading during ordinary use does not excuse incomplete final validation.
- Follow explicit full-read duties; do not silently replace them with excerpts or summaries.
