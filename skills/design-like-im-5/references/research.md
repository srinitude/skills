# Current research

Load this file before pipeline step 3.

## Goal

Find current facts for this product. Do not redo the base case study work.

## Inputs

Use the intake, tool list, source rights, product files, and live platform rules.

## Method

Queue each source and view with a script. Keep one packet per page, screen, image, state, or motion clip. The model must inspect each useful view.

Do not start from a closed state list. Find states from the person's goal, prior act, task, data, and system. Check place, device, input, access, time, content, people, and risk. Record causes and change. Add, split, join, or drop states when proof changes.

Use empty, wait, partial result, error, repair, offline, permission, interruption, and success only as coverage prompts. Skip a prompt that does not fit. Add any state the product evidence reveals.

Record what the source says. Mark that as source fact. Record what you think it means. Mark that as an inference.

Seek one case that does not fit the main idea. Narrow the rule when proof does not travel.

For each source, save its link, date, platform, task, seen pattern, clash, scope, and trust. Mark gaps. Do not turn a source note into broad proof.

The model must complete the eye, brain, and touch checklist for each kept state. A script may prove that every answer exists. It cannot prove that an answer is right.

Apply the full open human sweep to each check. Use every named eye, brain, and touch factor. Add any new factor that current proof reveals. Never call the named list complete.

Run all hard failure and harm checks. Look for text and image clashes, lost content, blocked controls, and target clashes. Look for focus traps, lost cues, state conflicts, and dead ends. Also check bad design, bad output, and bad work methods.

Use each check's exact question, evidence needs, probe order, failure meaning, and decision rules. Do not swap it for taste, a score, or a nearby check.

## Primary basis

Use [W3C status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) for visible and stated change. Use [W3C input help](https://www.w3.org/WAI/WCAG22/Understanding/input-assistance.html) for error and repair.

Use [W3C cognitive access](https://www.w3.org/WAI/cognitive/) for attention, memory, words, time, and change. Use [NIST human-led design](https://www.nist.gov/itl/iad/human-centered-technologies/human-factors-human-centered-design) for review with people and tasks.

Use [Apple feedback](https://developer.apple.com/design/human-interface-guidelines/feedback) and [Apple undo](https://developer.apple.com/design/human-interface-guidelines/undo-and-redo) for response and safe repair. Use [Android state work](https://developer.android.com/topic/architecture/ui-layer/state-production) for state made from current inputs and events.

Use the [FTC dark pattern report](https://www.ftc.gov/reports/bringing-dark-patterns-light) for hidden cost, false rank, hard exit, false time, and unfair data choice.
