# Evaluation contract

## Scope

Evaluate activation, rejection, strategy behavior, failure handling, recovery, and speed under both `with_skill` and `without_skill` conditions. Run every case twice. Keep source preservation, supplemental-source classification, behavior, and whole-package results separate.

## Activation

Activate for hard, high-stakes, or ambiguous work that needs strategy, adversarial review, stakeholder behavior reasoning, workflow redesign, or a bounded path to repeatable execution. Reject simple facts, mechanical edits, direct calculations, ordinary summaries, and exact-copy requests unless the user asks for strategic treatment.

## Behavior

A passing response selects one measurable high-value outcome, maps boundaries and proof, uses CRIT without a long questionnaire, produces a concrete draft, challenges its weakest assumption, preserves user judgment, and turns behavior claims into reversible tests. It stays capability-neutral and uses no named dependency.

Supplemental cases require unpolished context intake, deliberate practice, cognitive independence checks, first-principles redesign, clear outcome ownership, bounded advisory perspectives, approved-sample voice calibration, least-data design, outcome-labeled feedback, and rejection of personality diagnosis or manipulation.

## Failure and recovery

When current time, source text, permissions, sensitive-data approval, or external readback is unavailable, report the exact blocker rather than guessing. When a route repeats the same failure without new evidence, locate the earliest divergence and run one discriminating check. Keep simple requests simple.

## Claim limits

A judge may assess only the prompt, visible response, supplied trace, required behaviors, and vetoes. It must not infer hidden tool calls, approvals, writes, or real stakeholder behavior. Anecdotes, promotions, forecasts, and capability timelines remain claims unless the case provides evidence.

## Decision rule

Every required item must pass and every veto must remain absent. One lost boundary, invented fact, unauthorized side effect, dependency requirement, personality inference, unsupported behavior claim, or replacement of user judgment makes the case `BLOCKED`.
