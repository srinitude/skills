# Route context

Read this file before using or changing a context capsule. The route asset owns paths and fields. This file owns how the model turns those paths into informed judgment.

## Read all five classes

Each major action has five kinds of support. Read every applicable item before acting.

- A reference gives meaning, proof rules, conflicts, or other sound readings.
- A script builds a packet or checks its shape. It never supplies a design verdict.
- An asset supplies fixed fields, owners, schemas, or route data.
- An example shows the rule in a full scene, including failure and recovery.
- An eval supplies a case that can disprove a shallow or partial reading.

Do not treat five file names as five votes. Each item contributes a different kind of context.

## Use the contribution text

Read the contribution beside each path before opening the file. It states why that file matters for this action.

After reading the file, state the exact fact, constraint, scene, counterexample, or field it adds. Record that path in `context_acknowledgements`.

If the file adds nothing to the current action, record the path in `missing_context` with the reason. Use `BLOCKED` when that gap prevents the claim.

## Keep judgment with the model

Scripts may confirm that a path exists, a route is complete, or a record has every required field. They may not pick a state or option. They may not judge pixels or ease.

Treat a script pass as proof of route shape only. Make every product judgment from current product evidence and the full context bundle.

## Ask rich questions

For each support item, ask what it adds to the current person, state, task, place, and device. Also ask about input, access, time, content, people, risk, and prior acts.

Ask what would change the reading. Seek proof against the first view. Find an edge case and one sound cause.

For eye work, inspect presence, relation, order, overlap, crop, scale, contrast, motion, and change across views.

For brain work, inspect truth, expectation, cause, memory load, choice cost, risk, feedback, uncertainty, and repair.

For touch work, inspect reach, target, spacing, timing, input mode, feedback, interruption, settings, and effort.

## Preserve creative room

Context bars weak claims. It does not close the option space.

Use references and evals to expose tensions, not to select one pattern. Use examples to understand a full scene, not to copy its surface. Use assets to keep fields stable, not to freeze product states.

Keep four unlike directions as the floor for creative action. Add, split, reverse, or combine directions when the current product evidence supports it.

## Handle conflicts

Follow source rights first. Bar harm next. Then guard access, clear use, and choice.

When two support files conflict, name both paths and the exact conflicting claims. Read the source owner and decision rules. Do not silently choose the easier path.

If the conflict remains open, return `BLOCKED` for that claim. Save completed safe work and the smallest evidence needed to resume.

## Finish a context pass

A context pass is complete only when every required path is acknowledged or named as missing. The saved record must separate observed fact, source claim, inference, judgment, and proposed change.

The route checker proves that the support exists. The model proves that it understood and used the support.
